# 版本批账（VERSIONS）

> **这是门禁节奏的机器真源**：`tools/ci/run_gate.sh` 读仓库根 `VERSION`，把版本号写进每趟
> 门禁报告的 `version` 列；一个版本号 = 一趟全量门禁（= 一个「小版本」）。
> 立据：[ADR-0046](../decisions/ADR-0046-版本批门禁节奏与单源版本.md)（修订
> [ADR-0030](../decisions/ADR-0030-模块册分册制与阶段批门禁节奏.md) §4 的「阶段批」为「版本批」）。
> append-only：每批**追加一节**，不回改历史节。

## 一、版本号语义（v0.MINOR.PATCH）

| 位 | 含义 | 谁升 | 升的时机 |
|---|---|---|---|
| `0` | 大版本**固定为 0** | —— | 对外发布 SDK 时才动（本期无发布需求，见 ADR-0046 §明确不做） |
| `MINOR` | **一个版本批** = 一次全量门禁覆盖的可观察增量 | 集成机（唯一发号器） | 全量门禁 **绿之后**、随批提交升号 |
| `PATCH` | 批内修复趟（同批次内的回归修复、文档更正、判据补漏） | 集成机 | 需要重跑全量才升；只跑窄检**不升号** |

三条硬规矩：

1. **升号与跑批是同一件事的两面**：升 `MINOR` 必须附一趟全量数字；跑全量而不升号 = 这批没收尾。
2. **窄检永不升号**：单卡自查（`--fast` / `gate_scope.sh` 路由出来的那几条）**不动 `VERSION`**。
   这条就是「别写个小功能就在那跑门禁」的正面表述——不跑批，就不升号，也就不占批的账。
3. **开发机不得改 `VERSION`**：它是全局册（ADR-0030 §2 单写者），开发机要升号走池条目或提案。
