## 1. 背景与目标

系统 `PhotosPicker`(UIA-011/012)的固有边界:**sheet 不可品牌化**、无相簿
浏览、无视频时长过滤、iOS 16 无选择序号徽标、批量体验受系统 UI 限制。
本任务自研 SwiftUI 相册浏览器替换系统 sheet —— **只覆盖"浏览 + 选择"**,
选择结果仍汇入既有 `importMedia(url:)` 链路(UIA-011 的挂载点按钮 + 胶水
原样保留,换的只是选择器本体)。

**设计参考**(只读源码提炼边缘 case 清单,不拷代码,红线 #10):
[ZLPhotoBrowser](https://github.com/longitachi/ZLPhotoBrowser)(结构清晰、
活跃)、[HXPhotoPicker](https://github.com/SilenceLove/HXPhotoPicker)
(Picker subspec 模块化)。调研结论(2026-10-04 时点:两者均活跃维护,
协议 Apache-2.0 / MIT)已固化在 ADR-0015,防止重复调研。

## 2. 关键架构事实(先说清,防方向跑偏)

**core 的 probe / 解码消费的是文件 URL**(C ABI:`probeMediaDuration` 等以
路径为入参),而 `PHAsset` 就地访问拿不到持久 file URL。因此:

> **自研浏览器不改变导入落盘路径。** 选中项仍要经系统/PHAssetResource
> 落成文件 URL 再 `importMedia`;它改变的是**选择 UI**,不是导入链路。
> "拷入沙箱 / 缓存复用 / 就地播放预览"的优化归素材库整理任务,两个任务
> 在"选中项 → 文件 URL"这一步汇合。试图在浏览器层跳过落盘 = 撞 PAL
> 不透明句柄红线(#2),不做。

## 3. 范围(MVP)

| 能力 | 说明 |
|---|---|
| 视频九宫格网格 | `PHFetchResult` 数据源 + `PHCachingImageManager` 缩略图缓存 |
| 相簿列表 | 智能相簿(最近项目 / 视频)+ 用户相簿,层级进入 |
| 多选序号徽标 | 选择顺序 1/2/3 角标(自研相对系统 sheet 的核心增量之一) |
| 视频时长角标 + 过滤 | min/max 时长过滤(如 < 1s 剔除),配置项暴露给调用方 |
| iCloud 未下载素材 | 本地可用性判断 + 拉取(进度 / 弱网失败路径收敛到既有 importError) |
| 权限三态 + 受限模式 | `.notDetermined/.authorized/.limited/.denied` 分支;`.limited` 补选入口 |
| 选择完成 → 导入 | 回调交付文件 URL 列表,汇入 `importMedia`(顺序 = 序号顺序) |

### 3.1 交互模式(v1.1,对齐剪映素材面板的连续导入流)

主流剪辑 App(剪映)的素材面板与通用相册选择器的本质差异:**选择与插入是
同一步**,不存在"选完→确认"的两段式。本选择器采用双模式:

```
默认(单击即插入):
  点 cell → cell loading 覆盖 → 落 tmp(iCloud 在此拉取)
    → async 交付 → importMedia 进时间线 → loading 解除 + toast
  面板保持打开,可连续点选(半屏抽屉,iOS detents medium/large 可拖拽收起)

「多选」显式模式(右上角切换 / 单击模式下长按 cell 直达):
  序号徽标 + 满选置灰 + 底部托盘 → 「添加（N）」批量交付 → 托盘清空
```

- **反馈闭环**:`onConfirm` 是 **async 回调**,VM await 到父层导入链路
  (runBatch → importMedia)返回才解除 cell loading —— loading 覆盖
  "落盘 + 进时间线"全程,不留"已松手但素材还没进时间线"的盲区。
- **串行化**:单击插入由 `isPreparingFiles` 守卫串行,快速连点不并发
  (importMedia 的 importInFlight 会拒绝重入,不给它触发机会)。
- 退出多选清空已选;批量添加成功后托盘清空,可紧接着选下一批(剪映语义)。
- 面板形态:iOS 半屏 detents + 拖拽指示器(16.0 内 API,不用 16.4+ 的
  presentationBackgroundInteraction);macOS 固定窗口。

## 4. 技术方案要点

1. **SwiftUI 主体,PhotoKit 数据面**:`PHFetchResult` 是 NATULLY 懒加载的,
   网格用 `LazyVGrid` + 缩略图 cell(必要时 `UIViewRepresentable` 包
   `PHImageView` 级别的 cell 以吃满缓存);纯逻辑(fetch 包装 / 时长过滤 /
   选择状态机 / 权限分支)抽可单测类型,SwiftUI 手势接线靠冒烟(同
   UIA-005/011 既定手法)。
2. **权限与隐私(相对 UIA-011 惯例的显式偏离)**:必须新增
   `NSPhotoLibraryUsageDescription`(project.yml info 段,高冲突文件)+
   App Store 隐私标签"照片或视频库"申报。受限模式用
   `PHPhotoLibrary` automatic limited selection 处理。
3. **与素材库整理任务的先后**:不硬依赖 —— 本任务先沿用"选中即落 tmp +
   importMedia"(D3);素材库整理落地后,落盘步骤替换为"拷入沙箱",
   浏览器不感知。
4. **macOS 适配**:`PHPhotoLibrary` 在 macOS 可用(macOS 照片图库),同一
   组件双端跑;相簿结构两端有差异,进开放问题。

## 5. 非目标

- ❌ 不做照片 / Live Photo / GIF 选取(当前模型与渲染仅支持视频;照片是
  独立增量,另行立项)
- ❌ 不做编辑 / 裁剪 / 相机(自研 CAM-* 已覆盖相机;编辑不在导入链路)
- ❌ 不做 Android / 鸿蒙端相册 UI(各自系统 picker,ADR-0015 §决策 4)
- ❌ 不做 iCloud Drive / "文件"路径(fileImporter 已覆盖)
- ❌ 不改导入链路落盘方式(见 §2)

## 7. 开放问题

1. macOS / iOS 相簿结构差异对组件抽象的影响(是否需要平台分支;
   禁止 `#if` 推断能力,一律运行时查询精神同样适用 —— 走 PhotoKit
   运行时返回值分支,不走编译期)。
2. 万级图库 `PHFetchResult` 变更增量刷新(插入 / 删除动画)的实现深度:
   MVP 可先整段 reload,增量优化是否单独立任务,启动拆解时定。
3. 缩略图请求的调度优先级(可见区优先 / 预取策略)与内存上限,实测后
   定参数。
4. 隐私清单(`PrivacyInfo.xcprivacy`)与 PhotoKit required-reason API
   的申报项清单,开工时对照 Apple 文档核。
