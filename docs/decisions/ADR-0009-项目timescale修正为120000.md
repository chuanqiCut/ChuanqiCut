# ADR-0009：项目 timescale 由 60000 修正为 120000

- 状态：**已接受**（2026-09-25，team-lead 决策）
- 修订对象：**ADR-0006**《有理数时间与项目文件版本模型》第 32 行
- 决策人：team-lead（传哲授权）
- 触发：CORE-001 实现时的实测发现

## 背景与问题

ADR-0006 第 32 行原定：

> 项目 timescale 统一取 **60000**（可被 24/25/30/60/1001 整除，覆盖主要帧率）。

**这句理由经实测证伪。** 60000 不能被 24000 整除（60000 / 24000 = 2.5），
因此 **23.976fps（= 24000/1001）的单帧周期 = 1001/24000 秒在 60000 网格下为 2502.5 tick，非整数**。

23.976 是电影与专业内容的主流帧率之一，不是边缘情况。原 ADR 称"覆盖主要帧率"不成立。

## 实测覆盖度对比

单帧周期在网格下是否为整数 tick：

| 帧率 | 周期 | @60000 | @120000 |
|---|---|---:|---:|
| 23.976 (24000/1001) | 1001/24000 | **2502.5 ❌** | 5005 ✅ |
| 119.88 (120000/1001) | 1001/120000 | **500.5 ❌** | 1001 ✅ |
| 29.97 (30000/1001) | 1001/30000 | 2002 ✅ | 4004 ✅ |
| 59.94 (60000/1001) | 1001/60000 | 1001 ✅ | 2002 ✅ |
| 14.985 (15000/1001) | 1001/15000 | 4004 ✅ | 8008 ✅ |
| 24 / 25 / 30 | — | ✅ | ✅ |
| 50 / 60 / 120 / 240 | — | ✅ | ✅ |

**@60000 不精确 2 种；@120000 不精确 0 种。**

## 决策

项目统一 timescale 由 **60000 改为 120000**（= lcm(60000, 24000) = 2⁶·3·5⁴）。

选型依据：120000 对 15000 / 24000 / 30000 / 60000 / 120000 全部整除
（商分别为 8 / 5 / 4 / 2 / 1），因此整个 NTSC 家族（分母 1001）与全部常见整数帧率
都能在项目网格上用**整数 tick** 表达，逐帧步进不再产生累积舍入误差。

## 关键澄清：本决策不排斥"素材原生 timescale"

ADR-0006 第 33 行「素材保留其原生 timescale，转换只在边界发生一次」**继续有效**。
本次改的是**项目时间轴网格**，不是强制所有时间用同一个 timescale：

- 素材 / 媒体时间：仍可携带自己的原生 timescale（`RationalTime` 本身带 `timescale` 字段）
- 项目时间轴：统一 120000，能无损容纳上述全部帧率的整数表达

两者是互补关系，不是二选一。

## 代价与评估

| 项 | 评估 |
|---|---|
| int64 上限 | INT64_MAX / 120000 ≈ 7.69e13 秒 ≈ **243 万年**（原 60000 为 487 万年）。减半但仍远超任何实际项目时长 |
| 存储 | `{value, timescale}` 序列化格式不变，`value` 数值变大不影响 int64 |
| 改动范围 | 常量 `kProjectTimeScale` 一处 + 依赖它的断言/注释。**现在改成本最低** —— 仅 CORE-001~004 使用该常量，PAL 接口（CORE-006）尚未开始 |
| 兼容性 | 项目文件版本模型需记录 timescale（ADR-0006 已要求序列化 `timescale` 字段），旧文件仍可按自身记录的 timescale 正确读取 |

## 为什么现在改而不是以后

BACKLOG 第 327 行规定「CORE-006 之前，任何 PAL 实现不得开始」。
一旦 PAL 接口（GFX/Media/Audio/Clock）铺开，timescale 会渗透进大量接口签名与平台实现，
届时再改就是跨层返工。**当前是改动成本的最低点。**

## 验证

- 单测覆盖：八种帧率 ×10000 次步进零漂移；新增 120000 网格下全帧率整数性验证
- 命令：`ctest -R core_time --output-on-failure`

## 后续

- 若将来出现 1001 之外的非常规时间基（如某些专业摄影机私有时基），
  需重新评估并另立 ADR，**不得就地改常量**。
