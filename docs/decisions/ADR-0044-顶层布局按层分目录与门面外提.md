# ADR-0044：顶层布局按层分目录，Swift 门面外提出 engine/

- **状态**：已接受（2026-10-16 传哲拍板，执行分批进行中）
- **日期**：2026-10-16
- **决策者**：传哲（拍板 14 项）+ 集成机（执行与记录）
- **依据**：`RESEARCH-018-仓库布局复勘与整改执行方案.md`（本轮复勘）+ `RESEARCH-011` §5.2/§7（前作）
- **相关**：ADR-0019（文档分层）、ADR-0031（壳化与功能 Pod 分治）、ADR-0033（源码共置与双 Pod 边界）、
  ADR-0034（分批推进）、ADR-0035（PAL→Platform）、ADR-0038（引擎 Pod 重命名与 FFmpeg 独立 Podspec）
- **取代/修订**：ARCH-005 §工程结构的目录树；AGENTS.md 红线 #6 的 shader 位置措辞

## 背景

传哲命题：「可读性太差；按模块一个文件夹；各平台壳工程各自文件夹；不要搞太深的层级」。

实勘（RESEARCH-018 §1）显示：**顶层已经大体合格，"每模块一个文件夹"在 C++ 侧已成立**
（`engine/core/cq/` 下 11 个模块目录）。真正的问题是名实不符与归属错位四类：

1. `apps/apple/packages/` 装的是 **Swift 源码**，名字却是"包/打包产物"语义，且在壳工程目录下再套一层，
   最深源码路径 9 层；
2. `engine/` 同时装 C++ 内核、Apple 平台实现、**Swift 对外门面**、3 个 podspec、二进制副本 ——
   而 `engine` 在剪辑语境里 = 内核引擎；
3. `bindings` 描述的是机制（FFI 绑定），不是角色（对外 API 表面）；`kotlin`/`arkts` 只有 `.gitkeep`；
4. 红线 #6 的 shader 两半（Portable 在顶层 `shaders/src`、Platform-Native 在 `platform/<p>/shaders/`）分居两处。

## 决策

### 1. 顶层 = 一层一名，层内 = 一模块一文件夹

```
engine/     纯 C++：core/cq/<module>/ + platform/<os>/ + shaders/{portable,native}/
api/        跨语言对外门面：api/swift/（将来 api/kotlin/、api/arkts/）
ui/         Swift UI 组件 Pod：ui/<Module>/（扁平；Android 开工时再拆 ui/android/）
apps/       壳工程：apps/apple/{ios,mac}/；apps/{android,ohos}/ 为显式预留空壳
tests/      unit/<module>/ 分模块 + golden/（含新迁入的 edit_plan 夹具库）
build/      唯一临时产物根；已有 spm/ xcode/ third_party/ gate-logs/ 分区，
            禁止再往 build/ 根扔新的具名目录（DerivedData-iOS-device / shell-ios /
            shell-mac2 / audio-check 这类一次性散目录一律并入既有分区或删除）
```

> **cmake 产物保持在 `build/` 根，不改成 `build/cmake/`**。理由：`build/` 根已有
> 5.3G 缓存（`build/CMakeCache.txt`），迁目录 = 缓存全废 + 一次全量重编，且
> 全仓 **43 处** `ctest --test-dir build` 命令（9 个 skill、`AGENTS` 真源、`docs/BUILD.md` 等）
> 全要连带改写。成本远大于"分区整齐"的收益 —— 与决策 2 里 CocoaPods 约束同一类判断：**工具链的
> 既成约定优先于布局洁癖**。

### 2. Swift 门面外提：`engine/bindings/swift/` → `api/swift/`

`ChuanqiCutEngine.podspec` 随之移到 `api/swift/`，其 pod 根由 `engine/` 变为 `api/swift/`，
`source_files` 由 `bindings/swift/Sources/ChuanqiCut/**/*.swift` 改为 `Sources/ChuanqiCut/**/*.swift`。
`kotlin`/`arkts` 的 `.gitkeep` 占位一并迁到 `api/` 下（保留预留语义）。

> **已落地（INFRA-032，2026-10-16）**：`git ls-files api` = 25、`engine/bindings` = 0、
> `git ls-files engine` 149 → **124**（差 **25**，不是任务卡估的 23 —— 24 个 bindings 文件 + 1 个 podspec）。
> 两处只有门面搬家才暴露的隐性连带项：① `Sources/ChuanqiCutCore/include/cq_sdk.h` 是**相对符号链接**，
> 搬家后必须重写目标（`../../../../../core/cq/cq_sdk.h` → `../../../../../engine/core/cq/cq_sdk.h`）；
> ② `ui/{SharedUI,ChuanqiCutEditor}/Package.swift` 的 `.package(path:)` 本地包身份取**目录名**，
> `bindings/swift` 与 `api/swift` 的末段同为 `swift` → `.product(package: "swift")` 不用改（运气，不是设计）。
> `ChuanqiCutCore` 的 pod 根**仍 = `engine/`**（决策见下「红线」第 3 条），本 ADR 已登记为既成事实。

### 3. UI 上提：`apps/apple/packages/` → `ui/`（扁平，模块名保留 `ChuanqiCut` 前缀）

模块名 = pod 名 = Swift module 名 = `import` 语句，改前缀要动 57 个文件的 import，收益仅目录排序 —— 不改。
`Sources/<Target>` 一层保留：SPM 强制，去掉就跑不了 `swift test` 窄检。

### 4. shader 并入 `engine/shaders/{portable,native}/`

Portable（GLSL→SPIR-V→MSL）与 Platform-Native 同处一个模块树，跟其唯一消费者
`platform/apple/gfx/` 相邻。空残壳 `shaders/generated/` 删除（真实产物一直落在
`build/generated/shaders/`，见 `engine/platform/apple/CMakeLists.txt:59`）。
AGENTS.md 红线 #6 的措辞随之修订：路径由 `shaders/src/*.glsl` 改为 `engine/shaders/portable/*.glsl`，
`platform/<platform>/shaders/` 改为 `engine/shaders/native/<platform>/`。

### 5. 明确不做的三种"看起来更整齐"的改法

| 不改法 | 理由 |
|---|---|
| C++ 与 Swift 扁平混进单一顶层 `modules/` | **目录名是本仓机器校验的判定依据**，见下「红线」第 1 条 |
| 合并 `.ai`/`.workbuddy`/`.agents`/`.zcode` 四套 agent 上下文目录 | `pitfalls.md` 已 215K 且是集成机真源，动它要连带改 AGENTS.md 8 项自检清单 + `sync_context.py` + 9 个 skill，收益只有资源管理器排序 |
| 把 AI 规则生成物改为 ignored + 本地生成 | 保持入库以让 clone 即用；只在 README 标注"5 个为生成物，禁止手改" |

## 红线（本 ADR 立下的硬约束）

1. **目录名不是给人看的装饰，是门禁的判定输入。** 至少三处机器校验按目录名/路径工作：
   - `tools/platform/check_platform_headers.py:241` 的 `CONTRACT_DIR_NAMES` 按目录名白名单决定扫不扫，
     扫描根写死 `engine/core/cq`；
   - `engine/ChuanqiCutCore.podspec:35,47,48` 的 `source_files` / `public_header_files` / `header_mappings_dir`
     按路径 glob 定义 public/private 边界（红线 #7 的执行点）；
   - `tools/ci/run_gate.sh:158-194` 五个门禁步骤写死包路径。
   **任何目录迁移必须同步这三处，且迁移后必须实跑门禁确认"扫到的文件数"没掉**——
   ADR-0035 的教训是：白名单没跟着改，门禁会**静默漏掉整个目录**，不报错、CTest 全绿、`git status` 看不出来。
2. **CocoaPods 的 pod 根约束优先于布局洁癖。** 被 Pod 消费的 vendored 二进制必须落在 podspec 同目录树下
   （`ChuanqiCutCore.podspec:101` = `vendor/libffmpeg.xcframework` 相对 pod 根解析）。
   因此**不存在"全仓一个二进制目录"**：只能是「`third_party/prebuilt/` 唯一构建归口 + 各 pod 根内 `prebuilt/`/`vendor/` 消费副本」，
   副本由构建脚本覆盖写入、永不入库（P84）。
3. **`ChuanqiCutCore.podspec` 的 pod 根仍 = `engine/`，本轮不动。** 它同时覆盖 `core/cq/**` +
   `platform/apple/**` + `vendor/`，把 pod 根拆到子目录会破 `header_mappings_dir` 与 vendored 接线（ADR-0038 附录）。
   后续若要"engine 完全纯净"，须另开 ADR 重议此条。
4. **一次只做一类全仓搬家。** `ui/` 上提与 `api/` 外提不得同批（ADR-0034 + 本 ADR 红线 1）。
5. **全仓机械替换必须显式排除 append-only 文件**（P103，ADR-0035 复发过一次）：
   `docs/handoff/*`、`docs/reviews/*`、`docs/reports/LEDGER-*`、`docs/tasks/TASK-*` 历史单卡、
   `.workbuddy/memory/2026-*.md`。只更新活文档（ARCH-005、docs/README、PLAN-*、模块册、TODO-POOL、skill）。

每批必跑并报告具体数字（不写"全绿"）：

# ↑ 单测走这个入口，不要直接敲 ctest：本机 cmake/ctest 不在 PATH，
#   build_core.sh:89 会从 CMAKE_BIN 推导 CTEST_BIN（CI 里 CMAKE_BIN=cmake 即可用系统 cmake）。
#   基线数字：Debug 段 `100% tests passed out of 52`（2026-10-16，INFRA-027/028 与 029 搬家后均复现，real 155.7s/155.9s）。
#   用例名与计数在搬家前后必须一致 —— 用 "$CTEST_BIN" --test-dir build -N 做排序 diff。
#   ⚠️ 取 `-N` 的时机：门禁的 Release 段会重新 configure 同一个 build/，

### 红线补充（本轮执行中新发现，P144）

**.gitignore 有两种静默失效写法**：行内 `#` 注释被当成路径的一部分；
含斜杠的模式（`shaders/generated/`）锚定到文件所在目录、**不**匹配任意层级。
改规则后必须打 `git check-ignore -v <目录>/x` 探针逐条核对返回行号 ——
INFRA-027 首版一次漏掉 4 条规则，全靠探针抓出来。

## 遗留（本 ADR 明知未解）

- **`engine/` 里同时住着 C++ 内核与两个 podspec，pod 根 = `engine/`（已登记事实，非待办）**：
  `ChuanqiCutCore.podspec` 的 `core/cq/**` + `platform/apple/**` + `vendor/libffmpeg.xcframework`
  全部相对 pod 根解析，三者必须在同一目录树下（决策 8 / 红线 3）。INFRA-032 落地后复核：
  **门面的外提没有改变这条耦合** —— 顶层 `engine/` 仍是「C++ 内核 + Apple 平台实现 + 2 个 podspec」，
  只有 `ChuanqiCutEngine.podspec` 迁出。要把 pod 根也拆干净（例如 `sdk/pods/`）**须另开 ADR**，
  并先解决 CocoaPods 的 vendored 同树约束。
- **TimelineKit 仍在本仓之外**（`/Users/zhuning/Documents/ChatGPT/zui`，非 git 工作树）。
  本轮只登记风险 + 加 Podfile 路径守卫，不收编。后果与缓解见 `TODO-POOL-门禁真机待办池.md`：
  新机器 `pod install` 必失败；组件源码含 TASK-UIA-045 就地改的 3 处均无版本控制。
  **将来收编的落点 = `ui/TimelineKit`。**
- 三套 manifest（CMake / SPM / CocoaPods）一致性校验工具未做，单独排期。
- `docs/research/RESEARCH-011` 的 J 项（文档数 ≈ 源码数）持续观察，不处理。
