## [1] 解封装 (Demuxing)

### 概念

把容器格式（MP4、MOV、MKV 等）解析成独立的音视频流。容器格式本质上是一个**文件系统**——它维护一张"索引表"表告诉你里面有几条轨道、每条是什么格式、数据块在文件里的偏移位置。

### 技术细节

```
MP4 文件结构 (ISO Base Media File Format, ISOBMFF):
┌─────────────────────────────────────────┐
│ ftyp box（文件类型声明）                  │
├─────────────────────────────────────────┤
│ moov box（元数据 —— 最重要的 box）         │
│  ├── track[0]  video                    │
│  │    ├── tkhd (track header)           │
│  │    ├── mdia                         │
│  │    │    ├── mdhd (media header)      │
│  │    │    ├── hdlr (handler: vide)     │
│  │    │    └── minf                    │
│  │    │         └── stbl (sample table) │
│  │    │              ├── stsd (sample description — codec 参数)│
│  │    │              ├── stts (time-to-sample 表 — 时间戳)    │
│  │    │              ├── stsc (sample-to-chunk 映射)          │
│  │    │              ├── stsz (sample 大小表)                 │
│  │    │              └── stco (chunk offset — 文件偏移)       │
│  │    └──                               │
│  └── track[1]  audio                    │
│       └── ...                           │
├─────────────────────────────────────────┤
│ mdat box（实际的音视频数据块）             │
│  chunk[0] → chunk[1] → ...             │
└─────────────────────────────────────────┘
```

**关键算法：stbl (Sample Table) 是解封装的核心**。它不是把文件拆开这么简单——需要按照 `stts` 表计算每个 sample（一帧）的 PTS（显示时间戳），按照 `stss` 表找到关键帧位置。

```cpp
// 解封装的核心逻辑概念：
struct Demuxer {
    // stts: time-to-sample — 每帧的 duration
    struct TimeToSampleEntry { uint32_t sampleCount; uint32_t sampleDelta; };
    vector<TimeToSampleEntry> stts;
    
    // stco: chunk offset — 数据块在文件中的位置
    vector<uint64_t> chunkOffsets;
    
    // stsc: sample-to-chunk — 每个 chunk 包含多少 sample
    struct SampleToChunkEntry { uint32_t firstChunk; uint32_t samplesPerChunk; };
    vector<SampleToChunkEntry> stsc;
    
    // 给定时间戳，找到对应帧在文件中的位置
    size_t findSampleAtTime(int64_t targetPTS) {
        // 1. 遍历 stts 累加 duration，找到目标 sample index
        // 2. 遍历 stsc 找到该 sample 属于哪个 chunk
        // 3. 查 stco 拿到 chunk 文件偏移
        // 4. 查 stsz 计算出 exact byte offset
        return fileOffset;
    }
};
```

## [2b] 视频解码 (Video Decode)

### 概念

将压缩的视频码流（H.264 NAL units / H.265 HEVC NAL units）解压缩为逐帧的原始像素数据（YUV 或 BGRA）。

### 编码格式本质

```
H.264 / AVC:
┌───────────────────────────────────────────────┐
│  帧内预测 (I-frame)       ← 完整图像，关键帧    │
│  帧间预测 (P/B-frame)     ← 只存差异(运动矢量)  │
│                                                   │
│  核心算法: CABAC + 运动估计 + DCT 变换           │
│  宏块: 16×16 像素块 — 编码的基本单元              │
│  GOP (Group of Pictures): I P B B P B B P ...   │
└───────────────────────────────────────────────┘

H.265 / HEVC:
┌───────────────────────────────────────────────┐
│  和 H.264 类似，但更高效                        │
│  宏块→CTU (Coding Tree Unit): 最大 64×64      │
│  相同画质下码率比 H.264 低 40-50%              │
└───────────────────────────────────────────────┘

ProRes (Apple 专业格式):
┌───────────────────────────────────────────────┐
│  帧内编码（每帧独立，无帧间预测）               │
│  按行编码（不同于块编码）                      │
│  解码极其简单 —— 几乎就是行程长度解码          │
│  ProRes 422 / ProRes 4444 / ProRes RAW        │
│  解码速度极快，适合编辑                         │
└───────────────────────────────────────────────┘
```

### 解码器内部流程

```
H.264 码流 (NAL units)
    │
    ├── NAL Unit 拆解 (start code 0x000001 分隔)
    │     ├── SPS (Sequence Parameter Set — 分辨率、帧率、级)
    │     ├── PPS (Picture Parameter Set — 编码工具标志)
    │     ├── IDR (Instantaneous Decoder Refresh — 关键帧)
    │     └── non-IDR (P/B 帧)
    │
    ├── Entropy Decode (CABAC / CAVLC)
    │     └── 从比特流重建 -> 残差系数 + 运动矢量
    │
    ├── 反量化 + 反变换 (Inverse DCT)
    │     └── 从频域系数重建 -> 空间域像素差值
    │
    ├── 运动补偿 (Motion Compensation)
    │     └── 用前面帧 + 运动矢量 -> 预测块
    │
    ├── 环路滤波 (Deblocking Filter / SAO)
    │     └── 消除块效应
    │
    └── → YUV420p 帧 (NV12)
```

**硬件解码器**（VideoToolbox）把以上整个流程都固化在专用硬件里，CPU 只需要发一个命令：


| API | 级别 | 用途 |
|---|---|---|
| **AVAssetReader** | 高 | 从文件读解码后的帧 |

- VT 硬解 4K H.265 一帧耗时：**< 0.5ms**
- FFmpeg WASM 软解同一帧：**~15-25ms**（差 30-50 倍）
- 16 路 1080p 同时硬解：M4 Mac 也能轻松处理
- 解码延迟：VT 硬解约 1-2 帧（pipeline 延迟），软解取决于 CPU 负载

## [2a] 音频解码 (Audio Decode)

### 概念

将压缩的音频码流（AAC、MP3、Opus 等）解压缩为 PCM 采样数据。

### 技术细节

```
AAC 解码流程：
AAC 码流 (ADTS/LOAS 帧)
    │
    ├── 比特流解析 (Noiseless Decoding)
    ├── 反量化 (Inverse Quantization)
    ├── 反 MDCT 变换 (IMDCT)
    ├── 联合立体声解码 (Mid/Side Stereo)
    └── → PCM 帧（Float32 或 SInt16）

PCM 格式：
  Sample Rate: 44100 / 48000 / 96000 Hz
  Bit Depth: 16 / 24 / 32-bit
  Channels: Mono / Stereo / 5.1 / 7.1
  Layout: Interleaved (L-R-L-R) / Planar (LLL...RRR...)
```

### Apple API

| API | 功能 | 推荐度 |
|---|---|---|
| **AVAssetReader** + audio track | 读取解码后的 AudioBuffer | ✅ 编辑首选 |
| **AVAudioEngine** | 播放 + 实时处理 | ✅ 预览 |
| **AudioQueue** | 低延迟播放 | ⚠️ 一般不需要 |
| **AudioConverter** | 转码 PCM ↔ 压缩格式 | ✅ 导出用 |
| **AVAudioFile** | 读写音频文件 | ✅ |

```swift
// AVAssetReader 读取音频
let asset = AVAsset(url: videoURL)
let audioTrack = try await asset.loadTracks(withMediaType: .audio).first!

let reader = try AVAssetReader(asset: asset)

    track: audioTrack,
    outputSettings: [
        AVFormatIDKey: kAudioFormatLinearPCM,
        AVLinearPCMBitDepthKey: 16,

        AVNumberOfChannelsKey: 2,
        AVSampleRateKey: 48000
    ]

reader.add(output)
reader.startReading()

while let sampleBuffer = output.copyNextSampleBuffer() {
    let audioBufferList = CMSampleBufferGetAudioBufferListWithRetainedBlockBuffer(
        sampleBuffer, 
        bufferListSize: &bufferListSize,
        bufferList: &audioBufferList,
        blockBuffer: &blockBuffer
    )

}
```

| Codec | 解码方式 | 1080p 视频参考 | 纯音频功耗 |
|---|---|---|---|
| AAC | 硬解（ANE / Media Engine） | 几乎零 CPU | < 0.1W |

## [3] 变换 (Transform: 平移/旋转/缩放)

### 概念

对视频帧做几何变换 —— 平移（pan）、旋转（rotate）、缩放（scale）、翻转（flip）、裁剪（crop）。这是最基本的空间操作，几乎所有剪辑场景都会用到。

### 算法细节

**齐次坐标 + 仿射变换矩阵（2D Affine Transform）：**

```
[ x' ]   [ a  b  tx ] [ x ]
[ y' ] = [ c  d  ty ] [ y ]
[ 1  ]   [ 0  0  1  ] [ 1 ]

其中：
  a, d: 缩放 (scaleX, scaleY)
  tx, ty: 平移 (translateX, translateY)
  b, c: 旋转 (sin/cos θ)

展开为像素坐标：
  x' = a·x + b·y + tx
  y' = c·x + d·y + ty
```

**插值算法**：由于变换后的像素坐标往往是浮点数，需要插值。

| 插值方式 | 质量 | 性能 | 适用 |
|---|---|---|---|
| Nearest Neighbor | 最低（锯齿） | 最快 | 像素风格、预览快速拖拽 |
| Bilinear | 中等 | 快 | 预览默认、日常缩放 |
| Bicubic | 好 | 中等 | 高质量缩放 |
| Lanczos | 最好 | 慢 | 最终导出 |

**在 GPU 上实现：**

```metal
// Metal fragment shader — 仿射变换
struct TransformUniforms {
    float2x3 affineMatrix;  // 2×3 仿射矩阵
    float2 canvasSize;      // 输出画布大小
    float2 sourceSize;      // 源帧大小
};

fragment float4 transform_fragment(
    VertexOut in [[stage_in]],
    texture2d<float> sourceTexture [[texture(0)]],
    constant TransformUniforms &uniforms [[buffer(0)]]
) {
    // 当前像素在输出画布中的归一化坐标
    float2 outputUV = in.texCoord;
    float2 outputPixel = outputUV * uniforms.canvasSize;
    
    // 用仿射矩阵反向映射到源帧坐标
    float2 sourcePixel = float2(
        uniforms.affineMatrix[0][0] * outputPixel.x +
        uniforms.affineMatrix[0][1] * outputPixel.y +
        uniforms.affineMatrix[0][2],
        uniforms.affineMatrix[1][0] * outputPixel.x +
        uniforms.affineMatrix[1][1] * outputPixel.y +
        uniforms.affineMatrix[1][2]
    );
    
    float2 sourceUV = sourcePixel / uniforms.sourceSize;
    
    // 边界裁剪
    if (sourceUV.x < 0 || sourceUV.x > 1 ||
        sourceUV.y < 0 || sourceUV.y > 1) {
        return float4(0);  // 透明
    }
    
    // 采样（硬件自动做 bilinear 插值）
    constexpr sampler s(coord::normalized, filter::linear);
    return sourceTexture.sample(s, sourceUV);
}
```

### Apple API

| API | 级别 | 说明 |
|---|---|---|
| **Metal vertex/fragment shader** | 低 | **推荐**——完全控制，性能最优 |
| **CIFilter + CIAffineTransform** | 高 | 方便但 GPU 调度不如手写 Metal |
| **CGAffineTransform (Core Graphics)** | CPU | 慢，不适合视频 |
| **AVMutableVideoComposition** + `sourceTrackIDForFrameTiming` | 中 | 系统级变换，不够灵活 |

### 性能

| 操作 | M4 Mac (每帧) | A17 Pro (每帧) |
|---|---|---|
| 纯平移（无插值） | < 0.01ms | < 0.02ms |
| 旋转 + 缩放 bilinear 插值 | ~0.03ms | ~0.05ms |
| 旋转 + 缩放 bicubic 插值 | ~0.08ms | ~0.12ms |

## [4] 特征识别 (Feature Detection)

### 概念

从视频帧中检测出人脸、人体、物体、场景类型等语义信息。对视频编辑器来说，**人脸检测（face detection）** 和 **语义分割（semantic segmentation）** 是最核心的两个任务——前者服务美颜美型，后者服务抠像和特效。

### 4.1 人脸检测

```
算法演进：
                    ┌────────────────────┐
                    │  Haar Cascade       │ ← 传统方法，OpenCV 年代的
                    │  2001 (Viola-Jones) │   滑动窗口 + 积分图
                    └────────┬───────────┘
                             │
                    ┌────────▼───────────┐
                    │  DPM                │ ← 机器学习特征 + SVM
                    │  2008 (Felzenszwalb)│
                    └────────┬───────────┘
                             │
                    ┌────────▼───────────┐
                    │  MTCNN              │ ← 深度学习 3 级级联
                    │  2016               │   轻量，移动端常用
                    └────────┬───────────┘
                             │
                    ┌────────▼───────────┐
                    │  RetinaFace / SCRFD │ ← 当前最先进
                    │  2019-2022         │   端到端，单阶段
                    │                     │   SCRFD 是 InsightFace 团队
                    │                     │   为移动端优化的版本
                    └────────────────────┘
```

**当前主流的 RetinaFace / SCRFD 架构：**

```
输入图像 (640×640)
    │
    ├── Feature Pyramid Network (FPN)
    │     └── 多尺度特征提取（检测大脸和小脸）
    │
    ├── Context Module (SSH / 可变形卷积)
    │     └── 增加感受野，提高遮挡检测能力
```


### 4.3 语义分割 (Semantic Segmentation)

把图像像素分类——哪些是皮肤、头发、背景、衣服、嘴唇、眉毛。

```
UNet 架构（当前移动端人体分割的主流）:
┌────────────────────────────────────┐
│  Encoder (下采样 — 提取特征)         │

│    Conv → BN → ReLU                  │
│    ↓ /2                               │

│    Upsample → Conv → BN → ReLU     │
│    ↑ + Skip                         │
```

## [5] 抠像 (Keying / Matting)

### 概念

从视频帧中分离出前景（人/物体）和背景，输出 **Alpha 通道**（每个像素的不透明度 0-1）。

### 5.1 色度抠像 (Chroma Key / Green Screen)

```
算法逻辑（逐像素）:
  for each pixel (r, g, b):
      if isGreenish(r, g, b):
          alpha = 0  (透明)
      else:
          alpha = 1  (不透明)

  isGreenish(r, g, b):
      // 最简单的办法：在 HSV/YCbCr 空间判断
      // YCbCr: 绿色在 Cb=0.4, Cr=0.3 附近
      cb = -0.169*r - 0.331*g + 0.500*b + 0.5
      cr =  0.500*r - 0.419*g - 0.081*b + 0.5
      dist = sqrt((cb - greenCb)^2 + (cr - greenCr)^2)
      return dist < threshold
```

```
更高级的色度抠像还做：
  ├── Spill Suppression（绿色溢出色抑制）
  │     └── 前景边缘绿色反射的自动消除
  ├── Edge Refinement（边缘细化）
  │     └── 头发丝级别的 alpha 过渡
  └── Despill（去溢色）
        └── 用相邻帧信息填充抠像造成的边缘空洞
```

### 5.2 AI 抠像 (Background Removal / Portrait Matting)

深度学习的肖像抠像比色度抠像强大得多——不需要绿幕，任意背景都能抠。

```
MODNet 架构 (移动端实时抠像，当前最实用):
┌─────────────────────────────────────────┐
│  Input: 512×512×3                       │
│    │                                     │
│  MobileNetV2 Backbone                    │
│    │ (低分辨率分支 + 高分辨率分支并行)      │
│    ├── Low-res Branch                    │
│    │    └── 语义特征（前景/背景分类）       │
│    ├── High-res Branch                   │
│    │    └── 边缘细节（头发丝）             │
│    └── Fusion Branch                     │
│         └── 融合 → 精细 alpha 通道         │
│                                          │
│  Output: 512×512×1 alpha matte           │
└──────────────────────────────────────────┘
```

**关键指标**——移动端抠像模型的目标：
- 推理速度：< 10ms/帧（ANE 上）
- 参数量：< 5M
- 边缘精度：< 1px 误差（头发丝区域）
- 支持全身抠像，不仅是半身

### Metal 实现

```metal
// 色度抠像 fragment shader
fragment float4 chroma_key_fragment(
    VertexOut in [[stage_in]],
    texture2d<float> sourceTexture [[texture(0)]],
    texture2d<float> despillLUT [[texture(1)]],  // 可选：溢色补偿 LUT
    constant ChromaKeyParams &params [[buffer(0)]]
) {
    constexpr sampler s(coord::normalized, filter::linear);
    float4 color = sourceTexture.sample(s, in.texCoord);
    
    // RGB → YCbCr (BT.709)
    float cb = -0.168736*color.r - 0.331264*color.g + 0.500000*color.b;
    float cr =  0.500000*color.r - 0.418688*color.g - 0.081312*color.b;
    
    // 色度距离
    float dist = distance(float2(cb, cr), params.greenScreenCenter);
    
    // 软边缘（用 smoothstep 代替硬阈值，得到自然过渡）
    float alpha = 1.0 - smoothstep(
        params.innerRadius,
        params.outerRadius,
        dist
    );
    
    // Spill suppression — 绿色反射消除
    if (alpha > 0 && alpha < 1) {
        // 边缘区域：降低绿色通道的贡献
        float spill = max(0, 1.0 - max(color.r, color.b) / max(color.g, 0.001));
        color.rgb -= spill * params.spillSuppression * color.g;
    }
    
    return float4(color.rgb, alpha);
}
```

## [6] 美颜 (Beauty / Skin Smoothing)

### 概念

有两层：**磨皮**（让皮肤看起来光滑）和 **美白**（让肤色看起来更白或更均匀）。本质上都是像素级处理——不是几何变形，是颜色值修改。

### 6.1 磨皮 (Skin Smoothing)

**算法演进：**

```
高斯模糊
  └── 全图模糊 → 均匀但不保留边缘 → ❌ 不能直接用

双边滤波 (Bilateral Filter)
  └── 保留边缘的高斯模糊
  └── 每个像素的权重取决于空间距离 + 颜色差异
  └── 慢！O(radius²)

引导滤波 (Guided Filter) ← 当前首选
  └── O(1) 时间复杂度
  └── 边缘保留、不会出现梯度反转（双边滤波的鬼影问题）
  └── 用引导图（通常是原图的低通版本）指导滤波过程

频率分解法 (磨皮的核心方法):
  └── 原图 → 低频层 (光滑/大尺度) + 高频层 (细节/噪声/毛孔)
  └── 对高频层做衰减（减弱毛孔、皮肤纹理）
  └── 重构 → 平滑皮肤 + 保留边缘
  └── 这是几乎所有商业美颜 App 使用的方法
```

**频率分解的 Metal 实现：**

```metal
// 1. 计算低频层（高斯模糊）
// 2. 原图 - 低频 = 高频层
// 3. 对高频层做非线性衰减
// 4. 低频 + 衰减后的高频 = 磨皮结果

kernel void beauty_smooth(
    texture2d<float, access::read> source [[texture(0)]],
    texture2d<float, access::write> output [[texture(1)]],
    texture2d<float, access::read> lowFrequency [[texture(2)]],
    texture2d<float, access::read> skinMask [[texture(3)]],
    constant BeautyParams &params [[buffer(0)]],
    uint2 gid [[thread_position_in_grid]]
) {
    float4 src = source.read(gid);
    float4 low = lowFrequency.read(gid);       // 低频（光滑层）
    float4 high = src - low;                    // 高频（细节层，含毛孔）
    float mask = skinMask.read(gid).r;          // 皮肤 mask
    
    // 高频衰减（只在皮肤区域）
    float attenuation = 1.0 - params.smoothStrength * mask;
    float4 result = low + high * attenuation;
    
    // 过渡带处理：防止皮肤/非皮肤边缘生硬
    float edgeSmooth = smoothstep(0.1, 0.5, mask);
    result = mix(src, result, edgeSmooth);
    
    output.write(result, gid);
}
```

### 6.2 美白 (Skin Whitening)

```
美白算法:
  ├── 肤色检测（YCrCb / HSV 肤色模型或分割 mask）
  ├── 亮度提升（对皮肤区域）
  ├── 色相偏移（从黄 → 粉/白）
  └── 饱和度微调

颜色空间操作:
  ▸ RGB → YCbCr (或 HSL)
  ▸ 对 Y/L 通道做曲线映射（提亮但不溢出）
  ▸ 对 CbCr 通道做颜色偏移（减少黄色分量）
  ▸ RGB ← 写回
```

### 6.3 商业美颜算法的门道

公开的磨皮算法（双边滤波/引导滤波/频率分解）只是基础——商业产品的"调参"才是护城河：

| 细节 | 影响 |
|---|---|
| **皮肤 mask 的精度** | 决定能不能区分皮肤和嘴唇/眉毛/眼周 | 
| **高频衰减曲线形状** | 决定"保留毛孔质感"还是"完全磨皮" |
| **亮度自适应阈值** | 亮区和暗区磨皮强度不一样 |
| **时域滤波** | 同一区域在连续帧之间稳定，不闪烁 |
| **过渡带宽度** | 磨皮区域和未磨皮区域之间的渐变宽度 |

| API | 功能 | 推荐 |
|---|---|---|
| **Metal Compute Shader** | 磨皮核心算法 | ✅ 必须手写 |
| **CIFilter** | 快速原型（但不够精细） | ⚠️ 原型 | 
| **Vision 分割** | 提供皮肤 mask | ✅ |
| **MPS (Metal Performance Shaders)** | 高斯模糊等基础操作 | ✅ 加速 |

| 美白 | ~0.1ms |

## [7] 美型 (Face Reshaping)

### 概念

通过变形改变脸型和五官形态——**瘦脸、大眼、小脸、下巴调整、鼻梁增高、微笑唇**等。这是几何操作，不是像素操作。

### 7.1 两种技术路线

```
路线 A: Mesh Warp（网格变形）—— 主流开源方案
  ┌─────────────────────────────────────────────┐
  │  1. 从 landmark 生成三角网格                   │
  │  2. 偏移目标区域的顶点                         │
  │  3. 逐三角面片做纹理映射（warp）                │
  └─────────────────────────────────────────────┘

路线 B: UV Offset Map —— 商业产品主流
  ┌─────────────────────────────────────────────┐
  │  1. 不在 CPU 上做三角剖分                      │
  │  2. 预生成一张 UV 偏移图（float 纹理）           │
  │  3. Fragment shader 按偏移量采样源像素          │
  │  4. 偏移图本身是稀疏 landmark 插值得到的         │
  └─────────────────────────────────────────────┘
```

### 路线 A: Mesh Warp (详细拆解)

```
┌───────────────────────────────────────────────┐
│  MediaPipe 468 点                              │
│    │                                           │
│  Delaunay 三角剖分                              │
│    │                                           │
│  ┌──▼────────────────────────────────────────┐ │
│  │  剖分结果: ~900 个三角形                     │ │
│  │                                            │ │
│  │  Input Mesh          Target Mesh           │ │
│  │  ┌─────┐             ┌─────┐               │ │
│  │  │●   ●│             │●   ●│               │ │
│  │  │ ╱ ╲ │  偏移顶点    │ ╱ ╲ │               │ │
│  │  │●───●│  ───────→   │●───●│               │ │
│  │  └─────┘             └─────┘               │ │
│  └────────────────────────────────────────────┘ │
│    │                                           │
│  每个三角形做仿射变换:                           │
│    └── 根据 Input UV → Target UV               │
│    └── Fragment shader 重映射像素               │
│                                                  │
│  瘦脸的顶点偏移计算:                              │
│    下颌顶点方向 = 顶点 - 下巴中心点                │
│    偏移量 = 方向 × 瘦脸强度 × 权重(距下巴中心)     │
│    权重 = Gaussian(距离, sigma)                   │
└─────────────────────────────────────────────────┘
```

**三角剖分的 CPU 开销**：Delaunay 三角剖分每帧 ~2ms（CPU），这是 Mesh Warp 路线最大的问题。

**Metal 顶点变形实现：**

```metal
// Metal vertex shader — 变形网格的顶点偏移
struct VertexIn {
    float2 position [[attribute(0)]];   // 原始网格顶点
    float2 texCoord [[attribute(1)]];   // UV
};

struct VertexOut {
    float4 position [[position]];
    float2 texCoord;
};

struct ReshapeParams {
    float2 jawCenter;      // 下巴中心
    float2 eyeCenterL;     // 左眼中心
    float2 eyeCenterR;     // 右眼中心
    float jawStrength;      // 瘦脸强度
    float eyeStrength;      // 大眼强度
    float chinStrength;     // 下巴调整
};

vertex VertexOut reshape_vertex(
    VertexIn in [[stage_in]],
    constant ReshapeParams &params [[buffer(1)]]
) {
    float2 pos = in.position;
    float2 uv = in.texCoord;
    
    // 瘦脸：下颌顶点内收
    float2 toJaw = pos - params.jawCenter;
    float jawDist = length(toJaw);
    float jawWeight = exp(-jawDist * jawDist * 0.01); // Gaussian 衰减
    pos -= normalize(toJaw) * params.jawStrength * jawWeight;
    
    // 大眼：眼眶周围顶点外扩
    float2 toEyeL = pos - params.eyeCenterL;
    float eyeDistL = length(toEyeL);
    float eyeWeightL = exp(-eyeDistL * eyeDistL * 0.05);
    pos += normalize(toEyeL) * params.eyeStrength * eyeWeightL;
    
    // 类似处理右眼、下巴等...
    
    VertexOut out;
    out.position = float4(pos, 0, 1);
    out.texCoord = uv;
    return out;
}

// Fragment shader — 纹理映射（插值采样）
fragment float4 reshape_fragment(
    VertexOut in [[stage_in]],
    texture2d<float> source [[texture(0)]]
) {
    constexpr sampler s(filter::linear);
    return source.sample(s, in.texCoord);
}
```

### 路线 B: UV Offset Map (商业产品方案)

```
不需要每帧三角剖分。流程：
  1. 人脸检测 → landmark（轻量模型，~2ms）
  2. 根据 landmark 更新 UV offset map 的参数
      └── 不是重新生成整张图，是更新几个控制参数
  3. Fragment shader 采样 offset map → 像素重映射

UV Offset Map:
  ┌──────────────────────┐
  │ 纹理 (float2 格式)    │
  │ 每个像素存储: (dx, dy) │  ← 原始像素需要偏移的量
  │ 离线预生成（基于标准脸） │
  │ 实时只更新控制参数     │
  └──────────────────────┘

优点:
  └── 不需要每帧 Delaunay 剖分
  └── 不需要上传顶点 buffer
  └── 整张图一次采样 → 极速
  
缺点:
  └── 不精准（不能逐顶点控制）
  └── 需要离线准备 offset map
```

### 常用美型操作

| 操作 | 顶点偏移方式 | 偏移区域 |
|---|---|---|
| **瘦脸** | 下颌顶点沿法线向内收缩 | 脸颊两侧（腮帮子） |
| **大眼** | 眼眶周围顶点沿径向向外 | 上下眼睑 + 外眼角 |
| **小脸** | 整体缩放因子 < 1 | 全脸轮廓 |
| **下巴** | 下巴顶点上下移动 | 下巴尖 |
| **鼻梁** | 鼻梁两侧的内收 | 鼻梁两侧 |
| **微笑唇** | 嘴角向外 + 上唇中间上提 | 嘴角 + 上唇 |
| **额头** | 额头顶点上下移动 | 额头发际线附近 |

### Apple API

没有现成的 API，需要手写 Metal shader。MediaPipe 的 landmark 检测可以集成。

### 性能

| 方案 | M4 (每帧 1080p) | 耗时分布 |
|---|---|---|
| Mesh Warp + Delaunay (CPU) | ~3ms | 检测: 1.5ms, 剖分: 1ms, 渲染: 0.5ms |
| UV Offset Map | ~1ms | 检测: 0.8ms, 采样: 0.2ms |

## [8] 图像画质增强

### 概念

对视频帧进行画质提升——超分辨率（SR）、去噪（Denoise）、去雾（Dehaze）、HDR 重建。

### 8.1 超分辨率 (Super Resolution)

```
传统方法: 
  └── 插值（bicubic、Lanczos）：只是放大，不增加细节

深度学习方法:
  └── SRCNN / ESRGAN / Real-ESRGAN
  └── 端到端：低分辨率图 → 高分辨率图
  └── 问题：慢，移动端 < 720p → 4K 需要 100ms+
  └── 适用：最终导出时作为"增强"功能，不做实时预览
```

**Metal 上的传统高质量放大（不做 AI 超分）：**

```metal
// Lanczos 插值（高质量放大）
kernel void lanczos_upscale(
    texture2d<float, access::read> source [[texture(0)]],
    texture2d<float, access::write> output [[texture(1)]],
    constant float2 &scale [[buffer(0)]],
    uint2 gid [[thread_position_in_grid]]
) {
    float2 srcCoord = float2(gid) / scale;
    float4 result = lanczosSample(source, srcCoord, 3); // 3x3 窗口
    output.write(result, gid);
}
```

### 8.2 去噪 (Denoise)

```
空间域去噪:
  └── 双边滤波 / NL-Means（非局部均值）
  └── 慢，O(N²)

时域去噪（视频特有 — 利用相邻帧信息）:
  └── 3DNR (3D Noise Reduction)
  └── 当前帧 + 前一帧/后一帧 → 平均
  └── 需要做运动补偿（Motion Compensated Temporal Filtering）
  └── 否则移动物体出现鬼影

AI 去噪:
  └── DnCNN / FastDVDNet
  └── 效果好但速度慢
```

**时域去噪在 Metal 上的核心挑战**：需要帧缓存 + 光流（Optical Flow）做运动补偿。

```metal
// 简单时域去噪（无运动补偿 — 只适用静态场景）
kernel void temporal_denoise(
    texture2d<float, access::read> current [[texture(0)]],
    texture2d<float, access::read> previous [[texture(1)]],
    texture2d<float, access::write> output [[texture(2)]],
    uint2 gid [[thread_position_in_grid]]
) {
    float4 curr = current.read(gid);
    float4 prev = previous.read(gid);
    float4 blended = mix(curr, prev, 0.3);  // 70% 当前 + 30% 前一帧
    output.write(blended, gid);
}
```

### 8.3 视频画质增强完整管线（商业级）

```
输入帧 (SDR / 低分辨率 / 有噪声)
    │
    ├── 去噪 (3DNR + NL-Means)
    ├── 去雾 (暗通道先验 / DehazeNet)
    ├── 色调映射 (如果 HDR ← SDR)
    ├── 锐化 (Unsharp Mask / CLAHE)
    ├── 超分 (可选，导出时用)
    └── → 输出帧
```

### Apple API

| API | 功能 | 推荐 |
|---|---|---|
| **MPS (Metal Performance Shaders)** | 高斯模糊、卷机、二值化等基础操作 | ✅ 去噪基础 |
| **Core Image** | CIGaussianBlur、CIUnsharpMask 等 | ⚠️ 方便但慢 |
| **CoreML** | AI 去噪/超分模型 | ✅ 效果最好 |
| **Apple ProRAW / HEIC** | 内置 HDR 处理 | ✅ 图片适用 |

## [9] 颜色处理 (Color Processing)

### 概念

色彩校正和调色——这是视频编辑器最核心的专业功能之一。不是滤镜，是精确的亮度/对比度/饱和度/色相/色温控制。

### 9.1 颜色空间

```
颜色处理的核心是理解颜色空间：
                                    ┌──────────────┐
         RGB (相机/显示)             │ 感知均匀空间  │
         sRGB / DCI-P3 / Rec.709    │  Lab / LCh   │
         Display P3                  │  HLS / HSV   │
              │                      └──────────────┘
              ▼                              │
         ┌──────────┐                        │
         │ Linearize│         ┌──────────────┘
         │ (去 Gamma)│        │
         └────┬─────┘        │
              ▼               ▼
         ┌──────────────┐   ┌──────────────┐
         │ Linear RGB   │   │  YCbCr       │
         │ (计算空间)   │   │  (视频压缩)  │
         └──────────────┘   └──────────────┘

为什么需要线性空间？
  └── Gamma 校正过的 RGB 不是线性的
  └── 在非线性空间做数学运算 → 亮度/饱和度结果不对
  └── 所有颜色处理都应在线性空间做

调色管线:
  RGB (Gamma) → De-gamma → Linear RGB → 调色操作 → Gamma → RGB
```

### 9.2 调色工具

**亮度曲线 (Curves)：**

```
输入亮度 (0-1)
    ↑
  1 ┤      ╱
    │     ╱
    │    ╱
    │   ╱
    │  ╱
  0 ┤─┴────────→ 输出亮度 (0-1)
    0          1

每个通道（RGB 分别或整体）都可以有一条曲线。
S 曲线 → 提亮亮部 + 压暗暗部 = 对比度增强
```

**色轮 (Color Wheels)：**

```
阴影 (Shadows)
    红 ← ─ ─ ─ → 青
    绿 ← ─ ─ ─ → 品
    蓝 ← ─ ─ ─ → 黄

中间调 (Midtones) — 同上
高光 (Highlights) — 同上

每个轮控制对应亮度范围的色彩偏移。
```

**3D LUT (Look-Up Table)：**

```
3D LUT 本质是一个 3D 查找表：
  Input: (R, G, B) — 33×33×33 = 35,937 个格点
  Output: (R', G', B')

插值：输入 RGB 不一定正好在格点上 → 四面体插值

IEEE 标准 LUT 格式: .cube (Adobe)
  TITLE "My LUT"
  LUT_3D_SIZE 33
  0.000000 0.000000 0.000000
  0.031250 0.000000 0.000000
  ...

应用 3D LUT 在 Metal 上：
  └── LUT 作为 3D texture（MTLTexture type3D）
  └── Fragment shader 用 RGB 做 texture 坐标直接查表
  └── 一次采样 = 颜色转换完毕，O(1) 复杂度
```

**Metal 实现：**

```metal
// 3D LUT 应用
fragment float4 lut_fragment(
    VertexOut in [[stage_in]],
    texture2d<float> source [[texture(0)]],
    texture3d<float> lut [[texture(1)]],  // 33×33×33 3D texture
    constant float &intensity [[buffer(0)]]
) {
    constexpr sampler s2d(filter::linear);
    constexpr sampler s3d(filter::linear, mip_filter::none);
    
    float4 color = source.sample(s2d, in.texCoord);
    
    // 去 Gamma（sRGB → Linear）
    float3 linearColor = srgbToLinear(color.rgb);
    
    // 查 3D LUT
    float3 lutColor = lut.sample(s3d, linearColor).rgb;
    
    // Gamma 回来（Linear → sRGB）
    float3 gradedColor = linearToSrgb(lutColor);
    
    // 强度混合
    return float4(mix(color.rgb, gradedColor, intensity), color.a);
}
```

### Apple API

| API | 功能 | 推荐 |
|---|---|---|
| **CIFilter (CIColorMatrix/CIColorCube)** | 基础颜色处理 | ⚠️ 原型用 |
| **Metal fragment shader** | 全部自定义 | ✅ 必须手写 |
| **MPS** | 矩阵运算，可辅助 LUT 生成 | ✅ |

## [10] 滤镜 (Filters / Effects)

### 概念

预定义的颜色/风格化效果——黑白、复古、胶片、赛博朋克等。和调色的区别：滤镜是"风格"不是"校正"。

### 技术实现

滤镜本质上就是一组预设的颜色变换参数或 LUT。

```
滤镜分类:

颜色滤镜:
  └── 黑白: 不同通道加权组合
      gray = 0.299*R + 0.587*G + 0.114*B
  └── 复古: 降低饱和度 + 色相偏移到黄褐色
  └── 胶片: 特定颜色响应曲线 + 颗粒 + 暗角
  └── 日系: 高亮度, 低对比, 青色调

风格化滤镜:
  └── 边缘检测 (Sobel/Canny) → 素描/漫画
  └── 马赛克/像素化 → 分块平均颜色
  └── 鱼眼/万花筒 → 几何变形 + 镜像
  └── 油画 → 双边滤波 + 量化颜色
```

**商业滤镜的本质**——大多数 App 里的"一键滤镜"就是一张 3D LUT：

```
滤镜 = 3D LUT + 强度滑块（0-100%）

所有滤镜"调参" = 设计者在 DaVinci Resolve 或其他软件里
调好一组颜色参数，导出为 .cube 文件，在 App 里做成 LUT。
```

所以滤镜系统在工程上很简单：

```
滤镜预设列表:
  ├── "日系清新" ← 日系.cube
  ├── "复古胶片" ← 胶片.cube
  ├── "黑白高对比" ← 黑白.cube
  └── ...

应用流程：
  1. 用户选择滤镜 → 加载对应 .cube LUT
  2. Fragment shader 查表（和调色共用同一个 3D LUT shader）
  3. 切换滤镜 = 换 LUT 文件，shader 不用改
```

### Metal 实现

```
// 滤镜 + 原图叠加（强度控制）
fragment float4 filter_fragment(
    texture2d<float> source [[texture(0)]],
    texture3d<float> lut [[texture(1)]],
    constant float2 ¶ms [[buffer(0)]]  // (intensity, 其他)
) {
    float4 color = source.sample(s2d, uv);
    float4 filtered = sample_lut(lut, color);
    return mix(color, filtered, params.x); // params.x = 强度
}
```

## [11] 转场 / 开场动画 (Transitions)

### 概念

**转场**：两个相邻 clip 之间的过渡效果（划入、淡入淡出、溶解、卷页、3D 翻转等）。
**开场/结尾**：clip 的开始/结束动画（品牌露出、片头、片尾）。

### 11.1 转场算法

```
所有转场的本质是混合函数：
  output = mix(clipA, clipB, progress)
  
  其中 progress 从 0 → 1（转场过程）
  clipA: 前一个 clip 的尾部帧
  clipB: 后一个 clip 的头部帧

mix 函数决定了转场的类型：
  ┌──────────────────────────────────────────┐
  │ 淡入淡出 (Cross Dissolve)                  │
  │   output = lerp(A, B, progress)            │
  │   像素级线性混合                            │
  ├──────────────────────────────────────────┤
  │ 划入 (Wipe)                                │
  │   mask = step(progress, texcoord.x)         │
  │   output = mask ? A : B                     │
  │   按空间位置切换                             │
  ├──────────────────────────────────────────┤
  │ 滑动 (Slide)                                │
  │   A 平移移出 + B 平移移入                    │
  │   access UV 加偏移量                        │
  ├──────────────────────────────────────────┤
  │ 3D 翻转 (Page Curl / Flip)                  │
  │   需要 3D 几何 + 投影矩阵                    │
  │   Metal vertex shader 做顶点变换             │
  └──────────────────────────────────────────┘
```

**Cross Dissolve Metal 实现（最简单的转场）**：

```metal
fragment float4 cross_dissolve(
    texture2d<float> clipA [[texture(0)]],
    texture2d<float> clipB [[texture(1)]],
    constant float &progress [[buffer(0)]],
    VertexOut in [[stage_in]]
) {
    constexpr sampler s(filter::linear);
    float4 a = clipA.sample(s, in.texCoord);
    float4 b = clipB.sample(s, in.texCoord);
    return mix(a, b, progress);
}
```

**Wipe Transition（更复杂的）**：

```metal
// 带边缘羽化的划入转场
fragment float4 wipe_transition(
    texture2d<float> clipA [[texture(0)]],
    texture2d<float> clipB [[texture(1)]],
    texture2d<float> maskTexture [[texture(2)]],  // 自定义 wipe 图案
    constant float &progress [[buffer(0)]],
    VertexOut in [[stage_in]]
) {
    constexpr sampler s(filter::linear);
    
    float2 uv = in.texCoord;
    float mask = maskTexture.sample(s, uv).r;
    float edge = progress;  // 0 → 1
    
    // 软边缘
    float blend = smoothstep(edge - 0.05, edge + 0.05, mask);
    
    float4 a = clipA.sample(s, uv);
    float4 b = clipB.sample(s, uv);
    return mix(a, b, blend);
}
```

### 11.2 开场/结尾动画

```
实现方式更灵活：
  ├── 叠加层：透明度 + 平移/缩放的动画参数（关键帧驱动）
  ├── 参数随时间变化（从 0 → 1 → 0）
  └── 渲染时叠加在视频帧之上

关键帧驱动：
  ┌──── time=0s ────┬──── time=0.5s ──┬──── time=1s ──┐
  │ title: alpha=0  │   alpha=1       │   alpha=1     │
  │ title: scale=0  │   scale=1       │   scale=0.8   │
  │ title: pos=(0,0) │  pos=(0,0)     │   pos=(0,50)  │
  └────────────────────────────────────────────────────┘
  
  中间帧：按时间做 Hermite/Catmull-Rom 插值
```

### 12 标准转场类型清单

| 转场 | 算法复杂度 | 常见性 | Metal 实现难度 |
|---|---|---|---|
| Cross Dissolve | O(1)/像素 | ⭐⭐⭐⭐⭐ | 1 行 |
| Fade to/from Black | O(1)/像素 | ⭐⭐⭐⭐⭐ | 1 行 |
| Wipe (方向) | O(1)/像素 | ⭐⭐⭐⭐ | 2 行 |
| Slide | O(1)/像素 | ⭐⭐⭐⭐ | 坐标偏移 |
| Iris | O(1)/像素 | ⭐⭐⭐ | mask 圆 |
| Page Curl | 3D 几何 | ⭐⭐ | 需要网格 |
| Glitch / 故障 | 随机偏移 | ⭐⭐ | shader 骚操作 |
| 3D Flip | 投影矩阵 | ⭐⭐ | 需要 z-buffer |

## [12] 多轨合成 (Multi-track Compositing)

### 概念

将多个视频/图片/文字轨道按层级（Z-order）、混合模式（blend mode）、透明度叠加成一帧。

### 12.1 混合模式 (Blend Modes)

```
output = f(front, back)

Normal:       output = front
Multiply:     output = front * back
Screen:       output = 1 - (1-front)*(1-back)
Overlay:      根据 back 明暗选择 Multiply 或 Screen
Add:          output = front + back (clamp)
Alpha Blend:  output = front * α + back * (1-α)
```

**核心数学实现（Metal）：**

```metal
// 标准 Alpha 混合
fragment float4 alpha_blend(
    texture2d<float> frontLayer [[texture(0)]],
    texture2d<float> backLayer [[texture(1)]],
    VertexOut in [[stage_in]]
) {
    constexpr sampler s(filter::linear);
    float4 front = frontLayer.sample(s, in.texCoord);
    float4 back = backLayer.sample(s, in.texCoord);
    
    // Alpha 混合（标准 over 算子）
    float alpha = front.a;
    float3 result = front.rgb * alpha + back.rgb * (1 - alpha);
    return float4(result, back.a);
}
```

### 12.2 多轨合成管线

```
多轨合成 = 按 Z-order 从下到上逐层混合

Track 3 (最上层) ─── 文字/贴纸
    ↓ (混合模式: Overlay)
Track 2 ─── 画中画 (PIP)
    ↓ (混合模式: Screen)
Track 1 ─── 主视频
    ↓
Output (最终帧)

实现方式：
  var result = bottomLayer;
  for each layer from bottom to top:
      result = blend(layer, result, layer.blendMode)
```

### Apple API / GPU

```metal
// 多轨合成 Metal shader（处理多个 texture 输入）
// 注意：每个轨道是一层 texture
kernel void multi_track_composite(
    texture2d<float, access::read> track0 [[texture(0)]],
    texture2d<float, access::read> track1 [[texture(1)]],
    texture2d<float, access::read> track2 [[texture(2)]],
    texture2d<float, access::write> output [[texture(3)]],
    constant CompositeParams &params [[buffer(0)]],
    uint2 gid [[thread_position_in_grid]]
) {
    float4 result = track0.read(gid);       // 主轨道
    
    if (params.track1Active) {
        float4 t1 = track1.read(gid);
        // 按 blend mode 混合
        result = applyBlendMode(result, t1, params.track1BlendMode);
    }
    
    if (params.track2Active) {
        float4 t2 = track2.read(gid);
        result = applyBlendMode(result, t2, params.track2BlendMode);
    }
    
    output.write(result, gid);
}
```

### 性能

| 轨道数 | 分辨率 | M4 合成时间 | 瓶颈 |
|---|---|---|---|
| 2 轨 | 1080p | ~0.05ms | GPU 带宽 |
| 4 轨 | 1080p | ~0.1ms | GPU 带宽 |
| 6 轨 | 1080p | ~0.2ms | GPU 带宽 |
| 2 轨 | 4K | ~0.3ms | GPU 带宽 |
| 6 轨 | 4K | ~1ms | GPU 带宽 |

### 13.3 预览场景下的 CVMetalTextureCache

```swift
// 解码 → 渲染 → 显示的最优路径
let textureCache: CVMetalTextureCache

// 1. AVFoundation 解码出 CVPixelBuffer（零 CPU 开销）
// 2. CVPixelBuffer → MTLTexture（零拷贝）
CVMetalTextureCacheCreateTextureFromImage(
    nil, textureCache, pixelBuffer, nil, 
    .bgra8Unorm, width, height, 0, &texture
)

// 3. Metal 渲染管线处理
// 4. 输出到 CAMetalLayer 的 drawable
guard let drawable = metalView.currentDrawable else { return }
let blitEncoder = commandBuffer.makeBlitCommandEncoder()!
blitEncoder.copy(from: outputTexture, to: drawable.texture)
blitEncoder.endEncoding()
commandBuffer.present(drawable)
commandBuffer.commit()
```

|---|---|---|

## [14] 音频处理 (Audio Processing)

### 概念

对 PCM 音频数据进行均衡（EQ）、动态处理（压缩/限制）、混响（Reverb）等效果。

### 14.1 数字音频基础

```
PCM (Pulse Code Modulation):

采样点序列:
  [0.1, 0.2, -0.3, 0.5, -0.1, ...]
   ↑
   每个采样点 = 振幅

时间域 vs 频率域:
  ┌───────────────────────────────────────────────────┐
  │ 时间域（时域）: 直接操作采样点                      │
  │   音量调整: output[i] = input[i] * gain            │
  │   淡入淡出: output[i] = input[i] * ramp(i)         │
  │                                                    │
  │ 频率域（频域）: FFT 变换后操作                      │
  │   步骤源: input → FFT → frequency bins → 操作 →    │
  │           IFFT → output                             │
  │   EQ = 在频域对不同频率 bin 做增益调整               │
  └───────────────────────────────────────────────────┘
```

### 14.2 常用音频效果

| 效果 | 算法 | 实现方式 | 推荐 Apple API |
|---|---|---|---|
| **EQ (均衡器)** | IIR 滤波器组（Biquad） | 时域，逐采样点过滤 | AVAudioUnitEQ |
| **Compressor** | 动态范围压缩 | 时域，检测电平 → 增益衰减 | AVAudioUnitCompression |
| **Limiter** | 硬限制峰值 | 时域，ceil 最大值 | AVAudioUnitLimiter |
| **Reverb** | 卷积混响 / 算法混响 | 频域 / 时域 | AVAudioUnitReverb |
| **Delay** | 信号延迟叠加 | 时域，循环 buffer | AVAudioUnitDelay |
| **Noise Gate** | 低于阈值静音 | 时域 | AVAudioUnitEQ (部分) |
| **DeEsser** | 特定频率压缩 | 频域 | 需要自实现 |

**Metal 上的音频处理**——一般不用 Metal 做音频（苹果推荐 vDSP + AVFoundation），但如果你需要极致性能（比如几千轨混音），也可以走 Metal Compute Shader：

```metal
// Metal 上的简单音频音效（很少用，但可以做）
kernel void apply_gain(
    device const float *input [[buffer(0)]],
    device float *output [[buffer(1)]],
    constant float &gain [[buffer(2)]],
    uint id [[thread_position_in_grid]]
) {
    output[id] = input[id] * gain;
}
```

### Apple API（推荐路线）

```swift
// AVFoundation 音频处理管线 — 编辑场景
let engine = AVAudioEngine()
let player = AVAudioPlayerNode()

// EQ
let eq = AVAudioUnitEQ(numberOfBands: 10)
eq.bands[0].filterType = .parametric
eq.bands[0].frequency = 100
eq.bands[0].gain = -3  // dB
eq.bands[0].bypass = false

// Compressor

compressor.attackTime = 0.01  // 10ms
compressor.releaseTime = 0.1  // 100ms
compressor.threshold = -24    // dB
compressor.ratio = 4          // 4:1

// 连接: player → eq → compressor → engine.mainMixer → output

try engine.start()
player.play()
```

## [15] 变声 (Voice Changing)

### 概念

改变声音的特征——音调（pitch）和音色（formant）。常组合使用：提高 pitch 变"萝莉音"，降低 pitch 变"男低音"，调整 formant 变"机器人音"。

### 15.1 核心算法

```
音调 (Pitch) ← 振动频率（基频 F0）
  └── 女声 ~200-300Hz
  └── 男声 ~100-150Hz

音色 (Formant) ← 声道共振峰（决定"是这个人"的特征）
  └── 不变的"身份"信息
  └── PSOLA (Pitch Synchronous Overlap and Add)

变声算法:
  ├── 重采样法 (最简单，改变播放速度同时改变音调)
  │     output = resample(input, ratio)
  │     缺点：速度也变了（快进/慢放）
  │
  ├── PSOLA (时域)
  │     1. 找到基音周期（pitch period）
  │     2. 复制/删除周期（改变音调）
  │     3. 重叠相加平滑过渡
  │     优点：音调/速度独立控制
  │     缺点：人工感较强
  │
  ├── Phase Vocoder (频域，用 FFT)
  │     1. FFT → 频域
  │     2. 频域拉伸（改变音调）
  │     3. 频域压缩（改变速度）
  │     4. IFFT → 时域
  │     优点：独立控制 pitch 和时间
  │     缺点：瞬态信号（打击乐）效果差
  │
  └── World Vocoder (高质量，开源推荐)
        └── DIO + CheapTrick + MLSA 滤波器
        └── 分解为 F0 + 频谱包络 + 非周期性参数
        └── 可以独立控制 F0（音调）、频谱（音色）、速度
```

### Apple API

**系统没有原生变声效果器**。需要自己实现或使用第三方库：

```swift

    vDSP_Length(log2(fftSize)), FFTRadix(kFFTRadix2)
)

// Apple 官方没有封装好的变声 AU，需要自己写
```

**推荐的 iOS 端实现方案**：

```
方案 1: SoundTouch (C++ 库，有 iOS 移植)
  └── PSOLA + WSOLA
  └── 成熟的变速不变调 + 变调不变速
  └── MIT 协议

方案 2: DiracLE (商用)
  └── 最高质量的时域拉伸
  └── 用在专业音频软件里
  └── 付费

方案 3: Rubber Band (C++ 库)
  └── 高质量，支持实时处理
  └── GPL (注意合规)
```

## [16] 变速 (Speed Change / Time Stretch)

### 概念

改变视频播放速度——快放（speed > 1）或慢放（speed < 1），同时可选择保持音调不变（"变速不变调"）。

### 16.1 视频变速

```
视频变速直接修改解码时间戳：
  正常: frame at t=0.0, 0.033, 0.066, 0.1 ...
  2x:   frame at t=0.0, 0.066, 0.133, 0.2 ...
                          ↑ 跳过中间帧（丢帧）
  0.5x: frame at t=0.0, 0.016, 0.033, 0.05 ...
                          ↑ 插入插值帧（补帧）

插帧 (Frame Interpolation) 是慢动作的关键：
  ├── Frame Blending: 前后帧平均 → 模糊但快
  ├── Motion Interpolated: 光流 + 中间帧生成 → 清晰的慢动作
  └── AI 插帧: DAIN / RIFE / FILM (Apple)
       └── Apple 在 iOS 18+ 有 Frame Rate Interpolation API
```

### 16.2 音频变速（时间拉伸）

```
音频时间拉伸 = 改变长度（速度）但不改变音调。

WSOLA (Waveform Similarity Overlap-Add):
  └── 最常用的实时时间拉伸算法
  └── 不涉及 FFT，时域直接处理
  
  步骤:
  1. 从输入中取一个 analysis window
  2. 在目标位置附近搜索最相似的波形片段
  3. 重叠相加合成输出
  4. 步进到下一个 window
  
  优点: 实时、低延迟、语音效果好
  缺点: 音乐效果不如 Phase Vocoder
```

### Apple API

| 功能 | API | 推荐 |
|---|---|---|
| 视频变速 | `CMTimeMapping` / `AVMutableCompositionTrack.scaleTimeRange` | ✅ 系统原生 |
| 视频插帧 | CMTime / 降低 FPS 播放 | ⚠️ 需要自行实现 |
| 音频时间拉伸 | AVAudioUnitTimePitch | ✅ 系统原生 |
| 音频变速（保持音调） | AVAudioUnitTimePitch.pitch | ✅ |

## [17] 多轨混音 (Audio Mixdown)

### 概念

把多个音频轨道混合成一个（Master Output）。每条轨道有自己的音量、声相（pan）、静音/独奏设置。

### 技术细节

```
混音数学：
  output[i] = Σ (track[j][i] * gain[j] * panFactor[j])

  其中：
    gain[j] = track j 的音量 (0.0 - 1.0)
    panFactor[j]:
      pan = -1 (全左): L = gain, R = 0
      pan = 0 (中):    L = gain * 0.707, R = gain * 0.707
      pan = 1 (全右):   L = 0, R = gain
    i = 采样点索引

混音 = 浮点数乘加运算 = vDSP 最擅长的操作
```

### Apple API

```swift
// AVAudioEngine 的混音是自动的
// engine.mainMixerNode 自动做多轨混音

// 手动混音（导出时用 vDSP 加速）
import Accelerate

func mixdownAudio(tracks: [[Float]], gains: [Float], frameCount: Int) -> [Float] {
    var output = [Float](repeating: 0, count: frameCount)
    
    for (trackIndex, track) in enumerate(tracks) {
        let gain = gains[trackIndex]
        
        // vDSP_vsma: 向量乘标量再加到另一个向量
        // output[i] += track[i] * gain
        vDSP_vsma(
            track, 1,          // source
            &gain,              // scalar multiplier
            output, 1,          // accumulator
            &output, 1,        // result
            vDSP_Length(frameCount)
        )
    }
    
    return output
}
```

## [20] 封装 (Muxing)

### 概念

将编码后的视频（H.264 NAL units）和音频（AAC frames）按容器格式规范写入文件。

```
MP4 文件的写入过程:

1. 写 ftyp box（声明 MP4 版本）

    └── 要么编码完成后一次写入

  ┌──────────────────────────────────────────────┐
  │ 模式 1: Normal (moov 在文件末尾)               │
  │  ┌─────┬────────────┬─────┐                    │
  │  │ftyp │  mdat      │ moov│                    │
  │  └─────┴────────────┴─────┘                    │
  │  缺点: 下载完才能播放                            │
  │                                                │
  │ 模式 2: Fast Start (moov 移到文件开头)           │
  │  ┌─────┬─────┬────────────────────┐            │
  │  │ftyp │ moov│  mdat              │            │
  │  └─────┴─────┴────────────────────┘            │
  │  优点: 边下载边播放                              │

```

## 管线整体性能总结

### 管线每环耗时汇总 (M4 Mac, 1080p, 60fps)

```
                                     宽松预算: 16.6ms (60fps)
                                     紧张预算: 8.3ms (120fps)
┌────────────────────────────────────────────────────────────────┐
│  1. 解封装 + 读取     < 0.1ms  (一次读取多帧)                   │
│  2. 视频硬解          0.3ms    (Media Engine 硬件)              │
│  3. Transform         0.05ms   (一个 fragment shader)          │
│  4. 人脸检测+Landmark 3.0ms    (MediaPipe / CoreML on ANE)    │
│  5. 抠像              2.0ms    (CoreML 分割 + Metal shader)   │
│  6. 美颜              0.5ms    (Compute shader)               │
│  7. 美型              0.5ms    (Mesh warp / vertex shader)    │
│  8. 图像增强          1.0ms    (CoreML / MPS)                  │
│  9. 颜色处理 3D LUT   0.05ms   (一个 texture sample)           │
│ 10. 滤镜              0.05ms   (和 LUT 共用 shader)            │
│ 11. 转场              0.05ms   (混合两个 texture)              │
│ 12. 多轨合成          0.1ms    (Alpha blend per track)         │
│ 13. 上屏              0.2ms    (Present drawable)              │
│                                                               │
│  总计 (典型场景):                                              │
│    ├── 无 AI (仅解码+变换+颜色+多轨)    ~0.8ms                  │
│    └── 带 AI (全管线: 美颜+美型+抠像)   ~7.8ms                  │
│                                                               │
│  余量 (60fps):                                                 │
│    ├── 无 AI: 15.8ms                                           │
│    └── 带 AI:  8.8ms                                           │
└────────────────────────────────────────────────────────────────┘
```

### 导出管线

```
导出 (1080p, 30fps, ~10min 视频):

渲染 → 编码 → 封装全部走完:

渲染-编码并行管道:
  ┌──────────────┐   ┌──────────────┐
  │ GPU 渲染帧 N  │──▶│ VT 编码帧 N  │
  └──────────────┘   └──────────────┘
         │                   │
         ▼                   ▼
  ┌──────────────┐   ┌──────────────┐
  │ GPU 渲染帧 N+1│──▶│ VT 编码帧 N+1│
  └──────────────┘   └──────────────┘
         │                   │
         ▼                   ▼
  ┌──────────────┐   ┌──────────────┐
  │ GPU 渲染帧 N+2│──▶│ VT 编码帧 N+2│
  └──────────────┘   └──────────────┘

渲染 ~8ms + 编码 ~2ms + 封装 ~0.1ms = 每帧 ~10ms
总时间: 10min × 30fps × 10ms = ~5分钟（约 2x 实时）
               
如果是简单管线（无 AI）:
  渲染 ~1ms + 编码 ~2ms = ~3ms/帧
  总时间: 3min（约 3.3x 实时）

ProRes 编码: ~1ms/帧 → 更快，但文件更大
```
