# ADR-0029：双机分工与门禁跑批节奏（模块归属 + 开发机编码优先 + 待办池）

> **节奏修订（2026-10-07 晚）**：「集成机日批」经实践偏重，改为**阶段批**（合并快检必做 +
> 全量门禁/真机按阶段触发），记录归口改**模块册分册制**——见 [ADR-0030](ADR-0030-模块册分册制与阶段批门禁节奏.md)。
> 本文其余规则（两级完成定义、池 append-only、模块归属）继续有效。

- **状态**：已接受（2026-10-07，传哲拍板：「划分模块区分开发，不要跟远端撞车；只有本机具备真机与门禁能力，其他设备简化、把剩余门禁/真机记录进 TODO 推远端，由本机完成；传哲每天定期跑门禁和真机，开发中优先完成编码任务」）
- **关联**：[PLAN-三线并行](../tasks/PLAN-三线并行.md)（§1a 模块归属表、§2 号段）、[TODO-POOL-门禁真机待办池](../tasks/TODO-POOL-门禁真机待办池.md)、pitfalls P51/P78/P80/P81/P82、ADR-0019 §4（编号纪律）
- **影响面**：流程与文档（零代码）；真源 `.ai/source/AGENTS.root.md`「双机分工与门禁节奏」节；各 `.ai/modules/*.md` 头部归属行

## 背景

双机并行已运行两轮，暴露三类事实：

1. **撞面靠事后裁定，成本高**：UIA-015/016、CAM-015/016 两轮撞号，加上更早的双会话同日各取
   ADR-0016（P51）。号段协议（集成机发号）解决了 ID 撞号，但**模块级归属没有成文**，
   「哪台机器动哪个模块」全靠临场默契。
2. **开发机跑不了全量门禁，却按同一口径验收**：P78（`swiftc -parse` 当验收，38 处类型错误
   进主干）证明远端设备的自验不可信；真机（iPhone 17 Pro）只接在集成机侧。
3. **双机同改一处管理文档必然分叉**：2026-10-07 两台机器同日各自执行同一份 TODO-1 撞号清扫，
   结论同向但编号分叉（本机 4f6401e→4f0aa67 弃用重做）。管理类文档是多写者冲突区。

同时，传哲**每天定期跑门禁与真机**（本机）——门禁是批次性活动，开发会话中等门禁只会阻塞编码。

## 决定

1. **模块归属表（成文）**：全部 `.ai/modules/*` 模块逐一归属 A（编辑器/UI）/ B（相机/特效）/
   C（内核/媒体/渲染）/ 集成机 四个归属，见 `PLAN-三线并行.md` §1a；各模块文档头部加归属行。
   **一机同一时间只待一条线**，跨线需求拆卡或走集成机（既有 §1 规则不变）。
2. **两级完成定义**：
   - 开发机「编码完成」= 编码完 + **模块级自查**（编译 + 相关单测；Swift 必须 `-typecheck`，
     `-parse` 绿不是绿，P46/P48/P49/P78 案底）+ 上下文同步 8 项 + 待办池登记 + 推送。
   - 集成机「验收完成」= 全量 `run_gate.sh` 通过 + 真机验收 + 池条目关闭带数字。
     远端"已验证"一律按未验证处理（既有规则，P78 再证）。
3. **门禁/真机待办池**：`docs/tasks/TODO-POOL-门禁真机待办池.md` 是「待集成机处理的门禁/真机
   待办」唯一入口。开发机收工时**追加（append-only，格式照池文件）**；
   **池的清扫/关闭/编号改动只归集成机**——管理文档单写者，同改必分叉（背景 3）。
4. **集成机日批节奏**：每日定期 fetch → 合并守门（流程 A：全量门禁重跑 + 写集越界检查）→
   消化待办池 → 真机一趟多单（iPhone 17 Pro 检查点合并执行，传哲操作）→ 数字回填
   baselines/任务卡 → 关条目。真机项**攒一趟执行**，不来一趟跑一单。
5. **编码优先**：开发会话优先完成编码任务，门禁/真机经池异步消化，不为等门禁阻塞编码。
   **例外不豁免**：热点文件（`cq_sdk.h`、CMakeLists、构建脚本、真源、CI）与 ABI/依赖变更
   仍须先提案给集成机，不许先斩后奏。

## 后果

- 正向：撞面从「事后裁定」变「事前归属」；开发机不再被全量门禁阻塞；真机按日批攒单执行；
  管理文档回到单写者，编号分叉根因消除。
- 代价：主干可能短期带病进（开发机自查 ≠ 门禁）——由集成机日批兜底，P0 发现即冻结该线
  合并（PLAN §4 既有分级处置不变）。
- 8 项上下文同步清单**不简化**（它与门禁能力无关，且有连续漏做的案底）。
- 反转条件：若开发机频繁把 P0 送进主干（日批一周内 ≥2 次 P0），对该线恢复「合并前全量门禁」
  硬门，缩回简化档。
