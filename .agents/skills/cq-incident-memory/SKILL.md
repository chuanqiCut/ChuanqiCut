# 故障记忆

## 触发
构建失败且原因不明显 / 运行时崩溃 / 渲染结果错误 / 性能回归 / 回滚 / 设备特有问题。

## 流程
1. **复现**：拿到最小复现步骤与失败样本（媒体文件、项目文件、日志）。没有复现路径就不算定位。
2. **定位根因**：区分"根因"与"表象"。若答案是"看起来是 X 的问题"就还没到位。
3. **修复**：最小改动修复，并补上能捕获该问题的测试。
4. **防复发**：能否用规则/CI/静态检查/类型系统让它不再发生？
   - 能用工具拦住的 → 加进 CI 或 lint
   - 只能靠人注意的 → 写进 `.ai/modules/` 的硬约束
5. **回写记忆**

## 回写位置
| 内容 | 位置 |
|---|---|
| 可复用排障步骤、根因 | `.ai/memory/pitfalls.md` |
| 设备特有问题与降级决策 | `.ai/memory/device-matrix.md` |
| 实测数据 | `.ai/memory/baselines.md` |
| 由此产生的架构约束变更 | 新增 ADR，或更新 `.ai/modules/*.md` |

## 条目格式（必须）
```markdown
### <简述>
- 现象：
- 根因：
- 影响范围：（哪些平台 / 版本 / 设备）
- 排障步骤：（可复用，写清命令）
- 修复：
- 防复发规则：
- 日期 / 来源 / 验证状态：verified | hypothesis
```

## 检查清单
- [ ] 有最小复现步骤
- [ ] 根因已定位（不是表象）
- [ ] 补了能捕获该问题的测试
- [ ] 有防复发措施（工具拦截 or 硬约束）
- [ ] 已回写到正确位置，含日期与验证状态
- [ ] 未把一次性任务状态写进长期记忆

## 注意
未验证的推测必须标 `hypothesis`，不得写成事实。记忆污染比没有记忆更糟。
