# 设备矩阵与降级清单

> **2026-09-23 确认（传哲）：性能基线 = 高端满足、中端可用、明确不适配低端机。**
> 低端机不做降级适配，达标门槛以下直接明确不支持。

## 一、支持档位

| 档位 | 定位 | 门槛 |
|---|---|---|
| **高端** | 必须流畅：60fps 全效果链 | iPhone 13 Pro+/A15+；M1+ Mac；骁龙 8 Gen1+/天玑 9000+；RAM ≥ 8GB |
| **中端** | 必须可用：允许降预览分辨率 | iPhone 12/A14；骁龙 7 系/天玑 8000；RAM ≥ 6GB |
| **低端** | **不支持** | 门槛以下 → 明确提示不支持，不做降级适配 |

### "不适配低端"的确切含义（避免歧义）
- ❌ 不为低端机写专用降级路径（极简效果链、超低分辨率代理）
- ❌ 不做 4GB RAM 设备的内存裁剪
- ✅ 门槛以下给出清晰的不支持提示，而不是"能装但卡死"

### 仍然保留的安全网（这是防御性设计，不是低端适配）
- 能力缺失降级：无硬解 → 软解；无 compute → fragment（**中端机也可能缺某项能力**）
- 内存逼近预算：LRU 回收 + 降预览分辨率（防 OOM 的基本机制）

## 三、降级策略（能力缺失时）

| 能力缺失 | 降级路径 |
|---|---|
| 无硬件解码（某 codec） | FFmpeg 软解（`demux+codec-fallback` 档位）→ 不支持提示 |
| 硬解实例数不足 | 减少并发解码路数 → 复用实例 |
| 无 compute shader | fragment 等价实现 |
| 外部内存导入失败 | CPU 拷贝路径 |
| 无 NPU 推理 | GPU → CPU (XNNPACK) |
| 内存逼近预算 | 缩减帧缓存 LRU → 降预览分辨率（代理帧）→ 降并发路数 |
| 中端机 4K 预览帧率不足 | 降预览分辨率至 1080p，导出仍用原分辨率 |
