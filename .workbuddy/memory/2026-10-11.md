## 08:30 · 传哲在 clone `CocoaPods/Specs` —— 实测劝停并给替代路径

传哲执行 `git clone https://github.com/CocoaPods/Specs.git -- cocoapods`，问怎么快速 clone 下来。

### 结论：这个 clone 不用跑完
1. **体量**：`CocoaPods/Specs` 实测 **1.26 GB**、103,383 个 pod（GitHub API 实测）。
2. **源已弃用**：官方 `github.com/CocoaPods/Specs.git` 自 2022 年起被 CDN
   `https://cdn.cocoapods.org/` 取代；本机 `~/.cocoapods/repos/trunk` 已是 CDN 源
   （CocoaPods 1.17.0），`pod install` **不需要全量 spec**。
3. **要找的东西不在这里**（决定性）：官方 trunk 上 `其创作 SDKKit` / `其媒体引擎层` 均只有
   **`0.0.1` 占位版**，`其编辑语义层` / `其轨道 UI 组件库` / `其依赖注入层` / `EffectSDK_iOS_TOB` 各 1 个版本；
   而 `其公开 spec 仓库` 里有 **315 / 111 / 12 / 10 / 6 / 6** 个版本，且整个仓库只 **3.99 MB**。
   → **历史版本全在该厂商自己的 spec 仓库，不在 CocoaPods 官方。**

### 给出的替代路径（已验证）
- 查某个 pod 的所有版本：`curl https://trunk.cocoapods.org/api/v1/pods/<Name>`
- 本机直接看 spec：`pod spec cat <Name>`（CocoaPods 1.17.0 可用）
- **确认某 pod 在不在官方源：下 `https://cdn.cocoapods.org/all_pods.txt`（仅 1.5 MB /
  103,383 行）后 grep** —— 本次已下到 `/tmp/allpods.txt`，命中该厂商系：
  `其创作 SDKKit` / `其编辑语义层` / `其轨道 UI 组件库` / `其依赖注入层` / `EffectSDK_iOS_TOB` /
  `EffectBytedEffectSDK`(4.3.2) / `该厂商海外品牌RTC` / `BytedanceOpenPlatformSDK` 等。
- 万一真要 clone 全量，最快是 partial clone：
  `git clone --filter=blob:none --no-checkout <url>`（只取 commit+tree，文件内容按需拉）。

### 落盘

### 教训（可复用）
**找 pod 的历史版本，先分清「包管理器的官方索引」和「厂商自己的 spec 仓库」**：
官方索引常常只有厂商推送的少数（甚至占位）版本，厂商自建 spec 仓库才是全量。
判据就是查两边版本数差一个数量级就说明方向错了。
