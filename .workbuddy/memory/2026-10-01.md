## 我本轮完成的部分

### 1. 装上 CocoaPods（上一轮遗留）

- 系统 Ruby 2.6.10，无 brew / rbenv / rvm
- 关键发现：`~/.gem` 路径有权限限制（`Operation not permitted @ apply2files`）
  → 换 `--install-dir /tmp/cqgems` 后，同样的 gem、同样的 Ruby 编译成功
- 依赖链上几个 gem 的新版本已不支持 Ruby 2.6（ffi ≥3.0、drb ≥2.7、i18n ≥3.1）
  → 按 CocoaPods 官方 issue #12145 的做法，先手动锁定旧版再装主包
- 结果：`pod --version` → **1.11.3**

### 2. 修掉了 podspec 两处「看着对但不合法」的配置

都是 `pod lib lint` 抓出来的：
1. `module_map` **不能设在 subspec 上**（CocoaPods 明确禁止）→ 移到根 spec
2. `header_mappings_dir` 要求所有 public header 都在该目录内，
   而 `pal/apple/*.h` 是 PAL 内部头 → 去掉该设置

修完后 `pod lib lint --quick` → **passed validation**。

## UIA-003 调研：A 路径（先扩展 C ABI 渲染接口）的真实前置

传哲选 A（先扩展 C ABI 暴露渲染接口，再接真实画面）。调研后发现
**C ABI 不是第一道关卡**，真正的阻塞在更下面两层：

1. **PAL `RenderTargetDesc` 无法接纳外部 drawable**（core/include/cq/pal/gfx.h:71）
   —— 只有 width/height/format，没有外部原生纹理字段。
   而 MTKView 的 currentDrawable.texture 必须由 MTKView 持有，内核拿不到，
   也就无法把渲染目标指向它。
   （GraphicsDeviceDesc 有个 NativeImageHandle surface，但那是设备级可选字段，
    gfx_metal.mm 未使用。）

2. **GFX 编排层未实现** —— core/src/gfx/ 不存在，IGfxDevice 只有接口声明
   （文件头写明"实现由 RENDER-001 / GFX-002 落地"）。
   pal/apple/gfx_metal.mm 已实现。预览若现在做只能直连 PAL。

3. **即使接口通了也没有真实帧可显示** —— 预览需要 MODEL-001 时间线模型
   （未做）+ PALA-011 硬解（已实现但未接入 session）+ PALA-002 零拷贝导入
   （已实现但未接入）。所以做完接口，预览最多渲染测试图案。

建议方案 A2（离屏渲染 + 导出中性句柄，不破坏 PAL 冻结接口，每帧一次 GPU blit）；
**不要**走"读回像素 → Swift 再上传"的 CPU 往返路子（会毁掉预览帧率）。
