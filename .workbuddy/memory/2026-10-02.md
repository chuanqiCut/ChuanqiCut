## BIND-003 子步骤 5：C ABI 预览封装（2026-10-02 深夜）

### 核心矛盾与解法
C ABI 门面要装配预览就得拿平台能力，但 **core 从不调 PAL 工厂**（grep 全库确认）。
若 C ABI 按平台分裂实现，`cq_sdk.h` 作为「唯一对外边界」就废了。

解法 = **PAL 工厂 + 独立 TU**：
- `IBlitPass` + `CreateBlitPass` 移入 `pal/gfx.h`。它必然由平台原生 shader 实现，
  本就属 PAL；PAL 不能反向依赖 GFX，故给 `IGfxEncoder` 补 `PalEncoder()` 逃生口。
- 落地 `pal/media.h` 里**悬空 7 天**的 `CreateFrameProvider`（第 5 次「只有声明」）。
  core 侧 `PalFrameProvider` 把 PAL `IFrameProvider` 适配成 core `FrameProvider`。
- 两个调 PAL 工厂的 TU 必须独立：静态库按 archive member 拉符号 →
  「不用预览的目标」不被牵出 PAL 依赖。
  **实证**：`cq_tests_c_abi` 只链 cq_core、不链 cq_pal_apple，仍链接通过并运行成功。

### 顺带补的缺陷
- PAL `IFrameProvider::GetDuration` —— core 的 FrameProvider 要求此项，
  PAL 原本没有，适配时无处可取。

### 验收（c_abi_preview，32 项检查 0 失败，真正的 C TU）
- create(0,0)→NULL；register_asset/add_clip 成功；timescale=0 → 7000
- render(0.5s)→0，帧 pts=60000/120000；render(1.0s)→pts=120000（推进了）
- 空隙 5.0s → 1001 + last_hit_clip=0，仍返回可用纹理（黑）
- 未注册素材 → 7000；resize(128,128) 后仍成功；destroy(NULL) 幂等
