### 核验方式

### 核心事实
- **UI 层 22 项对照：9 项可用 / 4 项空壳 / 15 项无。**
  - 可用：导入(相册多选/iCloud/文件)、时间线 scrub、片段拖移、右缘裁剪、捏合缩放、

- Mac 比 iOS 还少：`EditorLayout.macLayout` 不调 `toolbar()` 槽位，六个按钮一个都不渲染。

## 23:00 · 传哲问「能不能根据二进制搞逆向」→ 分级回答并实测

**能做**：元数据层的只读静态观察。**不做**：反汇编/反编译还原实现逻辑
（商业 SDK EULA 普遍禁止；与 FFmpeg LGPL 同类，需法务商务拍板，AI 不代决）。

### 实测（其轨道 UI 组件库@0.1，armv7+x86_64+arm64，20MB）
- `lipo -info` → 三架构 20 MB
- `nm -arch arm64 -gU` → **108 个 OC 类 / 546 个实例变量 / 34 个协议**
- `strings` → 2604 个候选 selector、`dve_ui_*` 18 个 key

### 两个可直接用的对照结论
1. **`其多轨控制器` = 一个控制器 + 8 个「按片段类型划分的 ViewModel`**
   （视频/音频/滤镜/特效/贴纸/文字贴纸/调节/混合类型）—— 与 `color.json` 的按类型着色是
   同一套分类的两种表现：**片段类型是轨道 UI 的一等公民**，颜色、ViewModel、单元格三处都按它切。
2. **`其缩略图管理器` = 队列 + 锁 + 任务表 + 加载器 + 回调处理器**
   （`_operationQueue/_lock/_tasks/_loaders/_handlers`）—— 可直接对照我们的
   `TimelineThumbnailStore`（并发上限 3 / in-flight 去重 / LRU 240 / 失败记账），
   看我们是否漏了「handlers 分层」与「显式锁」。
3. 配置完整性自证：二进制里 `dve_ui_*` 恰好 18 个（color 15 + layout 3），与两份 JSON **完全对齐**
   → 配置确实全在外部 JSON，**看配置不必逆向，读 JSON 即可**。

### 踩坑
OC 方法名**不在** `nm -gU` 里（不是外部符号），grep `[-+]\[Class xxx\]` 命中 0；
要拿方法名得走 `__objc_methname` 段或 `otool -ov`，且 `.a` 需先 `ar -x` 解出 `.o`。

### 澄清一个误判
`.gitignore` 其实是干净的：`git ls-files -i -c --exclude-standard` = **空**，入库产物 0。
传哲看到的"编译文件夹混着"发生在**磁盘/开发者视野层**，不是版本库污染。区别很重要，
否则会去改一套本来就对的规则。磁盘实况：`apps/` 65662 文件 5.5G / `build/` 2.6G /
`third_party/` 11051 文件（含 277 个 .o in-source）/ `vendor/` 2509 文件 30M。

### 业界基准
检索 CMake Mastery Part16 + Common C++ Project Layouts + Conan/CMake 工程文章，
三份独立资料收敛结论一致：顶层 `CMakeLists.txt / cmake/ / src/ / include/<proj>/ / apps/ /
tests/ / docs/ / third_party/ / build/ / CMakePresets.json / README.md`。
**本仓库顶层其实大体合格**，偏离的是四条：构建根纪律没落到每条工具链、FFmpeg in-source、
`pal` 缩写不自明、缺 README/clang-format/CI。
