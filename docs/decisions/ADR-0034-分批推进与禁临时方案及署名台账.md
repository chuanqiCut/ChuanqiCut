# ADR-0034：分批推进·禁临时方案·署名台账·问卷驱动真机验收

- 状态：Accepted
- 日期：2026-10-10 21:47（CST）
- 决策者：传哲
- 执行与起草：WorkBuddy（对话引擎 Hy4 preview），同会话
- 关联：RESEARCH-010、ADR-0024、ADR-0029、ADR-0030、TASK-BACKLOG §3.6/§4.3
- 修正对象：**RESEARCH-008 §5「非目标」**、ADR-0024 隐含的「macOS 编辑页不作为」

## 背景

2026-10-10 上半场，集成机完成 `RESEARCH-010`（编辑功能现状核验），结论是 22 项对照中
9 项可用 / 4 项空壳 / 15 项无，硬伤为「无导出路径 + 无 SplitCommand」。该文档的 §6 提出两个
待拍板决策，其中决策 B 的倾向项是「文字先在 Swift 侧做临时实现，后续用内核管线替换」。

传哲对该推进方式提出否決，并要求调整工作方法：

> 不要急于立马完成，要有耐心，功能点要全部有而且要足够完善，技术方案要足够靠谱，
> 不能模仿一下就完了，要全局考虑；可以并行；不搞临时方案，按步就班，逐步推进，稳扎稳打；
> 代码要先一步一步写出来，然后给我问卷，我给真机表现；Mac 和 iOS 分开搞，按各自特性去支持；
> 方案要署名和时间，什么模型、什么时间做了什么决策，写了什么代码；我拍板了什么，做了什么调整；
> 便于后期发现和复盘，及时纠偏。

这段要求同时否決了「临时方案」与「先跑通形状再补功能」两种做法，并要求决策可追溯。
现有 ADR-0029/0030 只规定了**機lie分工与门禁节奏**，从未规定**交付粒度、质量下限与可追溯性**，
故立本 ADR 补齐。

## 决策

### 1. 节奏：分批推进，一批一闭环

- 功能按批次推进，每批有**书面出口标准**（用户可完成的操作路径，而非编译结果）。
- **一批未验收不得在其上叠加下一批**；不同批次之间可以并行，前提是写集不相交
  （沿用 AGENTS.md 写集规则，本 ADR 不放松）。
- 禁止"先把所有地方铺一层薄实现再逐个填"的做法 —— 那是伪并行，会把半成品固化成架构。

### 2. 质量下限：做全做透，不模仿形状

- 功能点要么**完整实现**，要么**明确列为"本期不做"并写进文件**，不存在"形状先到位"。
- UI 同理：不再有 `enabled:false` + 空闭包的占位按钮。
  **占位必须显式登记**，禁止用静默空闭包表达未就绪（与 pitfalls P99 同一件事，本 ADR 将其升为硬规则）。
- 「对齐对标 App」的含义由「界面形状相似」改为「**能力可用且行为正确**」。

### 3. 禁临时方案

- 任何标注"临时 / 先 XX 顶着 / 以后替换 / 本期先用 Swift 写"的实现 **一律不予采用**。
- 若某能力确实被未就绪的下层阻塞，**排队等待地基**，不允许在上层写绕过实现。
- 由此产生的排期后果（见 §「代价」）由传哲认可，不以进度为由回退本条。
- **本条直接否決 RESEARCH-010 §6 决策 B 的 B1 选项**（文字先 Swift 侧临时实现）。

### 4. 署名与时间：决策与实现台账（强制）

新建 `docs/reports/LEDGER-*.md`（**append-only**，按版本/年度分册）。每一次动代码或做决策，
必须登记以下字段，缺项视为未完成：

| 字段 | 内容 |
|---|---|
| 时间 | `YYYY-MM-DD HH:MM` + 时区 |
| 执行者 | 会话/工具/模型标识（如实填写，不写代号），以及是否集成机 |
| 决策 | 做了什么决定、依据哪份文档、替代选项是什么 |
| 写集 | 实际新增/修改的文件清单（含路径） |
| 验证 | 实际执行的命令 + 结果数字；**未跑就写"未执行"** |
| 拍板 | 传哲确认了什么、驳回了什么、要求了什么调整 |

沿用既有规则：决策记录要写进**文件**，不留在对话里（对话会丢，文件不会）。

### 5. 问卷驱动真机验收

交付节奏固化为四步：

```
写代码 → 生成《真机问卷》 → 传哲真机实测并回答 → 集成机纠偏登记<｜hy_place▁holder▁no▁813｜>
```

- 每次代码交付必须**附带问卷**（模板：`docs/reviews/TEMPLATE-真机问卷.md`），
  问卷含：改动清单与 commit、构建/门禁证据、**编号的检查点**（操作步骤 / 预期 / 实际表现留白）、
  已知偏差、本期明确不做项。
- **未经真机问卷回收的功能不得标记为完成**。集成机的门禁绿只能证明「能编能跑单测」，
  不能证明「在你手里是对的」。
- 检查点编号固定格式 `Q-<批号>-<序号>`，回收时按编号逐条回答，便于对照纠偏。

### 6. Mac 与 iOS 分端形态

- **不再把一套 iOS 视图塞进 Mac 窗口**。两端按各自特性走各自的产品形态：
  - **iOS**：移动端编辑范式（单焦点 + 抽屉式二级 + 底部工具栏 + 捏合缩放时间线 + 手势优先），
    沿用 UIA-034~038 已落地的 UIKit 三区结构。
  - **macOS**：桌面编辑范式（**常驻属性面板** + 顶部工具栏 + 多窗口 + 键盘快捷键 + 右键菜单
    + 拖拽导入 + 菜单栏命令体系），对标对标 App专业版桌面形态。
- 两端共享的**只有**内核 ViewModel 与 Command 链路（ARCH-005），**UI 布局与交互不共享**。
- 由此：**ADR-0024 隐含的「macOS 编辑页本轮不动」予以废止**，macOS 不再被视为套壳复用。

### 7. 撤销既有的一条非目标约束

- RESEARCH-008 §5「非目标：不复刻对标 App的内容能力（转场库/特效库/素材市场/关键帧曲线）」
  —— **该条自本 ADR 起作废**（素材市场/商业模式部分仍保留不作）。
- 后续产品目标以 RESEARCH-010 §4 的优先级为准：能力可用 > 形状相似。

## 理由

- 「稳扎稳打 + 禁临时方案」的本质是：**技术债不再作为排期工具**。临时实现一旦被 UI 依赖，
  替换成本会随每批功能增长，最终变成永久实现（本仓既有教训：相机滤镜 vs 编辑器特效两套实现，
  已在 `TASK-BACKLOG.md:414-415` 记为 ADR-0014 的代价，不应再犯第二次）。
- 「署名台账 + 真机问卷」解决的是可追溯性：AI 产出的代码量大且跨会话易丢上下文，
  没有台账就无法回答「这段代码为什么这么写、谁拍的板」。
- 「Mac/iOS 分端」是因为两端的诊断不同：现有 Mac 端连底部工具栏都不渲染
  （`EditorLayout.macLayout` 未用 `toolbar()` 槽位），这说明套壳路径本身就不成立，补丁没有意义。

## 代价与明确不做

- 禁用临时方案会使可见产出显著变慢：文字/贴纸/多轨必须等 `RENDER-001`（RenderGraph）
  + `MODEL-003`（属性系统）+ Portable shader 链就绪。**这是被接受的代价**。
- 台账与问卷是每批必做的固定开销，不允许省略；若某批代码量极小，也要登记一行。
- 本 ADR 不放松任何既有架构红线（AGENTS.md 十条一律有效），尤其不得为求快绕过 C++ 下沉。
