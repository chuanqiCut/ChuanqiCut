# UIA-012:相册多选批量导入

> 版本:v1.0
> 日期:2026-10-04
> 依赖:UIA-011(相册导入入口与 PhotoLibraryImporter 胶水,已落盘)
> 写集:`apps/apple/packages/SharedUI/Sources/SharedUI/Editor/PropertyPanelZone.swift`、
> `apps/apple/packages/SharedUI/Tests/SharedUITests/PhotoImportTests.swift`(追加用例)
> 选型依据:ADR-0015(相册选择器策略 —— 系统过渡、不引三方)

---

## 1. 背景与目标

UIA-011 落地的相册导入是**单选**:导入 N 条素材要 N 次进出系统选择器,批量场景
(多机位 / 分镜素材)体验差。本任务把 `PhotosPicker` 改为**多选**,一次选取一批
视频,逐条汇入既有 `importMedia(url:)` 链路。

仍是**系统 `PhotosPicker`**,零新依赖、零权限(PHPicker 进程外选择器不变)。
自研相册浏览器是 UIA-013(B 期),与本任务无依赖冲突,替换点同一个。

## 2. 行为定义

```
[从相册导入] → PhotosPicker(filter: .videos, maxSelectionCount: 20)
  → [PhotosPickerItem](按用户选择顺序)
  → 逐条 loadTransferable(URL.self)   // 系统把视频落到 tmp
  → 逐条 importMedia(url:)            // 追加到视频轨末尾,顺序 = 选择顺序
```

- **上限 20 条**:防一次性 tmp 拷贝体积失控(D3 引用 tmp 路径,批量会放大)。
  代码常量,开放问题 §6.2 留调整口。
- **顺序语义**:追加顺序应与用户选择顺序一致。iOS 16 上 `PhotosPickerItem`
  数组的顺序是否严格等于选择顺序**未实测**(开放问题 §6.1);iOS 17+ 有
  `selectionBehavior: .orderedAndContinuous` 可保有序,但基线是 iOS 16,
  不作为承诺,只作实测后兜底手段。
- **部分失败不中断**:某条 loadTransferable 失败 / 返回 nil URL,该条不产生
  素材,继续导入其余;结束后汇总展示(成功 M 条 / 失败 K 条,复用面板
  `importError` 展示位)。零成功仍走既有错误路径。
- **主线程纪律(红线 #8)**:`importMedia` 是主线程同步调用(见 AppEntry
  注释"用户动作、低频"),批量循环**逐条之间 `Task.yield()` 让出主线程**,
  不做整批同步循环;加载期间入口置 loading 态禁点(ViewModel
  `importInFlight` 双保险沿用)。
- **D3 放大警示**:N 条 tmp URL 在 App 重启后同样可能失效 → 素材列表批量
  「⚠ 已失效」。与单选行为一致,非本任务引入的回归;素材库整理任务统一收口。

## 3. 非目标

- ❌ 不做相册浏览 UI(网格 / 相簿 / 选择序号徽标)—— UIA-013(B 期)
- ❌ 不改 `importMedia(url:)` 签名,内核 / C ABI / Swift 绑定零改动
- ❌ 不做导入进度逐条展示(MVP 用整体 loading 态)
- ❌ 不做导入后台化 / 转码(probe 耗时实测若成为瓶颈,另立任务)
- ❌ 不支持照片 / Live Photo / GIF

## 4. 架构约束对照

| 红线 | 本任务 |
|---|---|
| #1 UI 不写业务逻辑 | 批量循环只是逐条调 `importMedia`,选批 / 汇总状态在 View 胶水层 |
| #8 主线程零阻塞 | 逐条 `Task.yield()` 让出,整批不同步占主线程 |
| #5 UI 不直接改模型 | 仍走 addClip Command,不变 |
| #10 依赖走 manifest | 零新依赖,不触发 |

跨端:iOS / macOS(SharedUI 共享)同步获得;Android 用系统 Photo Picker 的
多选(官方 API 自带),鸿蒙用系统 PhotoViewPicker,均不受本任务影响
(ADR-0015 §决策 4)。

## 5. 验收标准(可机器判定)

1. SharedUI `swift test --disable-sandbox` 全绿,新增批量用例(注入闭包手法
   同 PhotoImportTests):①注入 M 条成功 → 素材表 M 条且**顺序一致**;
   ②注入含 K 条失败 → 成功条入表、失败条不产生素材、汇总错误文案;
   ③批量期间 loading 态翻转、完成复位;④全失败 → 不产生素材不崩溃。
2. macOS App `xcodebuild build` 通过;iOS App legacy `-sdk iphoneos` 链
   编译通过(ui-apple.md 验证命令)。
3. `git diff --stat` 证明 write_set 外零改动(尤其 AppEntry.swift / core/ /
   bindings/)。
4. 人工验证(macOS 宿主):多选 3 条视频 → 时间线 3 个追加片段,顺序与
   选择一致,预览可播放。

## 6. 开放问题

1. **iOS 16 选择顺序保证**:`PhotosPickerItem` 数组顺序与用户选择顺序是否
   一致,需真机/宿主实测;不一致则评估升 iOS 17 `selectionBehavior`(需
   提基线变更)或明确"批量导入不承诺顺序"并写进头文件注释。
2. **上限值 20**:拍脑袋值 [E],按典型 4K HEVC 素材体积与 tmp 可用空间
   评估后可调;真机验证随 UIA-011 真机恢复一并执行(2026-10-04 延期决策)。
3. **macOS 系统 picker 多选表现**:macOS 版 PHPicker sheet 的多选交互
   与 iOS 有差异,宿主冒烟确认。
4. **批量 tmp 体积与清理时机**:归素材库整理任务统一收口,本任务只量化
   现象(若可测)。
