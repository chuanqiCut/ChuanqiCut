## 追加轮 4（UIA-013 v1.1：交互升级对齐剪映）

### 本轮做了什么
用户要求"对比主流如剪映的交互,要足够详细和专业"。Spec UIA-013 升 v1.1：
1. **单击即插入（默认模式）**——剪辑 App 与通用选择器的本质差异是选择与
   插入同一步。点 cell → loading 覆盖 → 落 tmp → async 交付 → importMedia
   → loading 解除 + toast"已添加到时间线"，**面板保持打开**（连续导入流）。
2. **async 交付回调**：`onConfirm: ([URL]) async -> Void`，VM await 父层
   runBatch 完成才解除 cell loading —— 反馈闭环覆盖"落盘+进时间线"全程，
   不留"松手了但素材还没进时间线"的盲区。`insertingIDs` 驱动覆盖层；
   `isPreparingFiles` 串行化快速连点（importInFlight 重入拒绝不触发）。
3. **「多选」显式模式**：顶栏切换按钮（长按 cell 单击模式直达 —— 相册 App
   经典手势）；退出清空已选；批量按钮「添加（N）」；成功后托盘清空。
4. **iOS 半屏面板**：presentationDetents(medium/large) + 拖拽指示器
   （16.0 内 API；16.4+ 的 presentationBackgroundInteraction 刻意不用，
   基线纪律）。
5. 测试 12→15 用例（插入全链路/时长过滤与失败/模式切换清空；确认交付后
   托盘清空断言）。PropertyPanelZone sheet 交付改 async、不再关闭面板。

### 关键设计事实
- async 回调是本轮的架构增量：交付从"通知式"变"完成式"，父层导入链路的
  耗时被计入 cell loading —— 这是单击即插入体验成立的前提。
- 长按手势挂 cell（minimumDuration 0.45s），多选模式下禁用（避免与拖拽
  语义冲突）。
- 时长过滤对单击路径同样生效（不进落盘，直接拒绝 + toast）。
