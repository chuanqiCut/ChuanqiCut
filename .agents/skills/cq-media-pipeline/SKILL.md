# 媒体管线改动审查

## 触发
改动涉及：解码 / 渲染 / 编码 / 封装 / 音频 / seek / 变速 / 倒放 / 音画同步 / 帧缓存。

## 必答的六个问题（写进 PR，缺一项不得合并）

### 1. 线程
- 这段代码在哪个线程执行？
- 是否可能阻塞主线程？（> 16ms 即违规）
- 音频路径是否加锁或分配？（**禁止**）

### 2. 时序
- 时间用 `RationalTime` 还是浮点？（**必须 RationalTime**）
- 涉及 TimelineTime / SourceTime / PresentationTime 的哪套坐标？转换在哪里发生？
- 变速场景：是否经过 `TimeMap`？倒放与速度曲线是否都覆盖？

### 3. 内存
- 新增的帧缓存/纹理是否有上界？
- 超预算时如何降级？（LRU / 降分辨率 / 降并发路数）
- 4K 三轨下的峰值预估是多少，是否触碰预算（见 `.ai/memory/baselines.md`）？

### 4. 取消
- 是否在 pass 边界与解码边界检查 `CancelToken`？
- 取消后 GPU 资源、媒体资源、临时文件是否全部释放？

### 5. 错误码
- 失败路径是否返回**稳定错误码**（不是崩溃、不是静默失败）？
- 能力缺失（如无硬解、无 FFmpeg codec）是否走查询 + 降级，而不是假设存在？

### 6. 一致性
- 预览与导出是否走同一张 RenderGraph？
- 与另一 FrameProvider 实现的行为是否一致（同 seek 请求同结果）？
- 三端（iOS/Android/鸿蒙）行为是否一致？

## 检查清单
- [ ] 六个问题全部有答案
- [ ] 新增了对应单测（时序、内存、取消至少各一）
- [ ] golden 对比已跑（渲染/导出相关）
- [ ] 性能数据已记录并与基线对比（不得用估算数字）

## 输出
PR 描述中包含"媒体管线分析"小节，逐条回答上述六点。
