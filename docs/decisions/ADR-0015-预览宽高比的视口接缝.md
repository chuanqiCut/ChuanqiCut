# ADR-0015：预览宽高比适配的接缝 = 编码器视口原语

- 状态：已接受（2026-10-04，UIA-011 落地）
- 关联：`TASK-UIA-011`、`ADR-0013`（泵线程与共享队列）、`ADR-0011`（core 调 PAL 工厂的隔离规则）、
  `.ai/modules/preview.md`
- 影响面：`core/include/cq/pal/gfx.h`（`ICommandEncoder` additive 扩展）、
  `core/include/cq/gfx/gfx_device.h`（`IGfxEncoder` additive 扩展）、
  `pal/apple/gfx_metal.mm`、`core/preview/preview_renderer.*`、
  `cq_sdk.h`（+1 setter）、`bindings/swift`、SharedUI AppEntry

## 背景

预览离屏画布与素材宽高比不同时，当前实现是**拉伸铺满**（IBlitPass 全屏拷贝）：
9:16 素材进 16:9 画布直接变形。该限制原记录在 `preview_renderer.h`「本期不支持」
清单与 `cq_sdk.h:281` 注释（「待 UI 需求明确后加」），现转正为 UIA-011。

核心问题：**这个「源矩形 → 画布矩形」的映射放在哪一层实现？**

## 决定

### D1：fit 是几何映射，用「视口」一个原语表达三种模式

| FitMode | 视口矩形 | 效果 |
|---|---|---|
| kStretch（默认 = 现状） | 整个 RT | 拉伸铺满（既有行为，golden 断言不变） |
| kContain | 源比例内切矩形居中（≤RT） | letterbox/pillarbox，bar 区 = 清屏色黑 |
| kCover | 源比例外接矩形居中（≥RT） | 裁剪铺满，超出 RT 的 fragment 被光栅化自动丢弃 |

三种模式**全部**是「把全屏 blit 变换到一个矩形」，不需要 shader 分支、不需要
uniform、不需要第二 pass。bar 之所以是黑的：清屏色黑 + 视口外不产生写入。

### D2：原语落在 GFX `IGfxEncoder::SetViewport` + PAL `ICommandEncoder::SetViewport`（additive）

备选与不选理由：

1. **给 `IBlitPass::Encode` 加目标矩形参数 / blit shader 加 uniform** —— 否。
   触碰冻结的 PAL blit 接口与其 MSL，连带破坏「SharedUI 侧 MSL 与
   `blit_fullscreen_msl.h` 逐值一致」的像素级锁定不变量（.ai/modules/preview.md §10），
   改动面与回归面都大；而视口是渲染管线的通用固定功能，与具体 pass 无关。
2. **在 SharedUI 的 RT→drawable blit 里做 fit** —— 否。那是恒等映射（像素级锁定），
   且 fit 属于「时间线画面是什么」的合成语义，归内核（红线 #1：业务逻辑下沉 C++；
   红线 #9：预览与导出同一张图 —— 未来导出走同一 RenderFrame，fit 自动一致）。
3. **视口原语**（选定）—— GFX/PAL 编码器各加**一个** additive 方法；Apple 实现
   直映射 `MTLRenderCommandEncoder.setViewport`（MTLViewport{originX, originY,
   width, height, znear=0, zfar=1}）。未来 GLES（`glViewport`）/ Vulkan
   （`vkCmdSetViewport`）天然对应。

**约定**：视口矩形为**像素**、原点 = render target **左上**（与既有 blit
uv(0,0)=左上 的方向约定一致）；Metal 1:1 映射，其他后端负责各自坐标转换。

### D3：fit 的计算与状态归 `PreviewRenderer`，默认 stretch

- 源尺寸 = `frame.video.width/height`（解码器已填充；0 = 尺寸未知 → 诚实退化
  kStretch，不猜测、不报错——退化为现状行为）。
- `FitMode { kStretch=0, kContain=1, kCover=2 }` 默认 kStretch：所有既有像素断言
  一字不改；产品装配（SharedUI AppEntry）显式设 contain。
- setter 跨线程（主线程调、泵线程读）→ `std::atomic<int>` 存储。泵线程模型
  （ADR-0013 D2）不受影响：视口在泵线程编码路径上设置。

### D4：C ABI 面 = 一个 setter

`cq_preview_set_fit_mode(CQPreview*, int32_t mode)`；非法值返回
`kInvalidArgument(7000)`。不设 getter、不加 create 参数（既有 ABI 签名不动），
Swift 侧 `Previewer.setFitMode` 薄投影。

## 后果

1. PAL 冻结接口（CORE-006）扩展了一个方法 —— additive、零破坏：不改既有签名、
   不移方法、不改枚举值，旧调用方字节码语义不变。本 ADR 即该扩展的评审记录。
2. cover 模式依赖「视口可大于 render target 且超出部分被裁」—— Metal 光栅化保证
   attachment 外无 fragment；GLES/Vulkan 同性质（超出视口/裁剪不写入）。若未来某
   后端不保证，退化为把 cover 实现为「contain 视口 + 内容放大」（pass 内再变），
   接缝不变。
3. fit 只作用于「源帧 → 画布」这一步；片段级变换（缩放/位移/旋转）是 MODEL-003
   属性系统的事，不混入本机制 —— UIA-011 落地后 `preview_renderer.h`
   「本期不支持」清单里「宽高比适配」一条移除，多轨合成与变速两条保留。
4. 无新增每帧分配；视口为栈上 4 个 float，一次性整数几何计算，无性能可测量项
   （baselines 不新增条目，标注不适用）。
