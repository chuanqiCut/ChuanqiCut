## 1. 背景与目标

现有导入入口只有 `.fileImporter`(系统"文件"选择器),iOS 用户要导入手机相册里的
视频必须先经过"文件"App,路径割裂。本任务在素材库面板新增**从相册选取视频**的入口,
选取后走**与 fileImporter 完全相同的导入链路**(probe → registerAsset → addClip),
时间线与预览立即可见。

### 选型:系统 PhotosPicker,不引第三方

用户许可"可采用第三方代码集成,后期再考虑自定义一套"。结论是**用系统
`PhotosPicker`(PhotosUI)**,理由:

1. 平台基线满足:iOS 16 / macOS 15.4(ADR-0010),`PhotosPicker` /
   `PhotosPickerItem.loadTransferable` 自 iOS 16 / macOS 13 起可用,**零新依赖**。
2. 第三方相册库(BSImagePicker / YPImagePicker 等)会触发架构红线 #10
   (`third_party/manifest.toml` 登记 + 协议评审 + commit 锁定 + SBOM),为一个
   系统框架已覆盖的能力背上长期依赖治理成本。
3. PHPicker 是**进程外选择器**:**无需** `NSPhotoLibraryUsageDescription`、
   无需相册读权限申请(用户选什么系统只给什么),隐私与审核成本最低。
4. "后期自定义一套"(缩略图网格 / 相簿侧栏 / 多选批量的自绘相册浏览器)的
   替换挂载点就是这一个按钮 + item→URL 胶水,届时换 UI 不动导入链路。

## 2. 行为定义

```
[从相册导入] 按钮 → PhotosPicker(filter: .videos, 单选)
  → PhotosPickerItem.loadTransferable(URL.self)   // 系统把视频落到 tmp 文件
  → EditorViewModel.importMedia(url:)              // 复用现有入口,一行不改
      → probeMediaDuration → registerAsset → addClip(追加到视频轨末尾)
```

- **只支持视频**(`PHPickerFilter.videos`),与 fileImporter 白名单
  (movie/video/mpeg4Movie)对齐;照片 / Live Photo 不在本期。
- **单选**,与现有 fileImporter 一致(多选批量导入是后续增强)。
- iCloud 未下载的视频由系统在 loadTransferable 内处理(可能慢 / 失败),
  失败走面板既有 `importError` 展示路径。
- loadTransferable 是异步的:加载期间按钮置 loading 态防重复点击
  (ViewModel 已有 `importInFlight` 防连点,View 层补视觉反馈)。

## 3. D3 决策沿用(重要)

相册视频的临时 URL 由系统管理(位于 tmp),**App 重启后可能被清理**。按 D3
(MVP 引用原路径不拷贝沙箱),重启后素材列表同样显示「⚠ 已失效」—— 与
fileImporter 路径行为一致,不是本任务引入的回归。素材库整理(拷入沙箱)是
既定后续任务,届时两条导入路径一起收口。

## 4. 非目标

- ❌ 不做自定义相册浏览 UI(缩略图网格 / 相簿侧栏)—— 后续任务
- ❌ 不引入第三方相册库 —— 见 §1 选型
- ❌ 不支持照片 / Live Photo / GIF 静态素材 —— 当前模型与渲染只支持视频
- ❌ 不做多选批量导入
- ❌ 不做"拷入沙箱"的素材落盘(沿用 D3,后续任务统一收口)
- ❌ 不动内核 / C ABI / Swift 绑定 —— 纯 SharedUI 层改动

## 5. 架构约束对照

| 红线 | 本任务 |
|---|---|
| #1 UI 不写业务逻辑 | 导入链路全部复用 `EditorViewModel.importMedia`,View 只做 item→URL 胶水 |
| #5 UI 不直接改模型 | 走 addClip Command,不变 |
| #10 依赖走 manifest | 零新依赖(PhotosUI 是系统框架),不触发 |

跨端:Android 的相册导入(Photo Picker / PICK_MEDIA)是 android-ui 侧独立任务,
不受本任务影响;SharedUI 是 Apple 端共享层,iOS / macOS 两个 App 同步获得该入口
(macOS 亦有照片图库,PhotosPicker 可用)。

## 6. 验收标准(可机器判定)

1. SharedUI `swift test --disable-sandbox` 通过(macOS 宿主),含新增用例。
2. macOS App `xcodebuild build` 通过(PhotosPicker 在 macOS 15.4 基线内编译)。
3. iOS App 用 legacy `-sdk iphoneos` 链编译通过(ui-apple.md 验证命令;
   本机无 iOS 运行时,运行时行为留真机验证,见开放问题)。
4. 新增 ViewModel 级测试:相册导入与文件导入**汇入同一入口**
   (`importMedia(url:)` 行为已被 MediaImportTests 覆盖,新用例锁
   "photoItem → loadTransferable 失败 → 不产生素材 / 不崩溃"的错误路径胶水)。
5. 相册选取真实视频 → 时间线出现追加片段 → 预览可播放(人工验证,
   macOS 宿主可全流程跑;iOS 真机不在本机验证,见 §7 决策)。
