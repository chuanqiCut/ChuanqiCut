# ADR-0020：智能成片与大模型（LLM）接入边界

- **状态**：提案（待批准）
- **日期**：2026-10-04
- **相关**：RESEARCH-003（竞品调研）、SPEC AIEDIT-001、ADR-0005（端侧推理：模型要框架不要）、ADR-0012（命令提交时机与撤销栈线程边界）、ADR-0009（timescale=120000）、`.ai/modules/ai.md`

## 背景

产品决定新增"智能成片"：导入素材 → 本地提取特征 → 大模型产出剪辑决策 → 本地 SDK 执行 → 导出或继续编辑；并保留对话框（文字 + 语音）做迭代调整；远期扩展"脚本→分镜"入口。这是**全仓首次引入网络与大模型**，涉及四个必须现在定死的架构问题：

1. 大模型调用放在哪一层（UI / core / PAL）？
2. 原始素材上不上云？
3. 大模型的输出用什么契约（自由文本 / 结构化 JSON / 直接生成时间线）？
4. 决策如何执行才能守住 Undo/Redo 与三端一致性？

已核验事实：
- 端侧无可用的第三方多模态视频理解模型（Apple FM / Gemini Nano 均文本为主，RESEARCH-003 §2.7）→ "理解"必须上云；但**特征提取可以且应该在本地做**（FrameProvider 精确取帧已可用，`cq_query_capability` 含 `npuInference`）。
- core / pal 目前**零网络设施**，manifest.toml 无任何网络依赖。
- 现有 Command 底座（6 种命令、CommandHistory、session 线程）可直接承载决策执行；转场等模型字段已在但缺命令类型。
- `cq_session_submit` 异步提交 + 快照 observer 机制（ADR-0012）——AI 决策执行与手动编辑**共用同一通道**。

## 决策

1. **原始素材默认不出设备。** 上云的只有"特征摘要"（`FeatureReport` JSON，KB 级）与用户消息。可选增强（上传少量低分辨率帧给云端多模态模型）必须显式授权开关，默认关闭，并在 UI 标注"将上传 N 帧画面"。
2. **分层边界**（与 `IInferenceBackend` 同构，红线 1/2/3）：
   - `core/include/cq/ai/`：`ILlmClient`（纯接口）、`EditPlan` schema 与校验器、`FeatureReport` schema、Prompt 构建、决策→Command 映射——**全部 C++，三端共享**。
   - `pal/<platform>/net/`：HTTP/SSE 传输实现（Apple 端用 URLSession 原生，不引第三方）。core 只见 `INetTransport` 抽象与 opaque 句柄。
   - UI（SwiftUI）：仅做触发、进度展示、对话框渲染、语音输入（系统 STT）；不解析决策、不拼装 Command。
3. **大模型输出契约 = `EditPlan`（版本化 JSON Schema）**，LLM 产出**有界 action 列表**（place/remove/trim/transition/…），不直接产出时间线。C++ 侧做唯一权威校验（schema 校验 + 引用完整性 + 时间合法性），失败自动修复重试（≤2 次），仍失败走本地规则引擎降级。时间字段一律 `{"value", "timescale"}` 有理数（红线 4），C++ 侧拒绝浮点秒。
4. **决策执行全走 Command**：每个 EditPlan action 映射为一组既有/新增 `ICommand`（经 `cq_session_submit` 提交）。AI 产物与手动编辑同一撤销栈——一次应用 = 一个可撤销批次。禁止 UI 或 AI 链路直接改 ModelSnapshot（红线 5）。
5. **供应商可插拔，协议收敛为 OpenAI-compatible chat/completions（含 SSE 流式）**：模型名、endpoint、key 走配置（`cq_ai_llm_config`），同一客户端代码可切 Gemini/Claude/豆包/通义。key 的分发方式（用户填写 / 服务端代理）是产品决策，不在本 ADR 范围。
6. **离线降级路径**（能力缺失降级红线）：无网/无 key/决策三连失败 → 本地规则引擎（静音剔除 + 质量排序 + 模板节奏）产出 EditPlan，走**同一条校验与执行链**。降级在 UI 明示。
7. **对话上下文存项目内**（会话消息 + 已应用 EditPlan 历史），不依赖服务端会话状态；服务端无状态化，便于换供应商。

## 备选方案

| 方案 | 否决理由 |
|---|---|
| 直接上传原始视频给云端多模态模型（剪映路线） | 隐私/流量/成本；与"素材不出设备"定位冲突。保留为显式授权的可选增强（决策 1） |
| 端侧 LLM 做决策（Apple FM / Gemini Nano） | 当前端侧模型不具视频理解；文本模型只吃特征摘要时能力上限低。保留为**降级路径候选**（无网但设备支持时，规则引擎 > 端侧 LLM 待验证，暂不实现） |
| LLM 直接输出完整时间线 JSON | 无界输出、难校验、难增量修改、难归因到 action 级理由；token 浪费。action 列表是可校验的有限动词集 |
| LLM 输出自由文本由各端 UI 解析 | 违反红线 1（业务逻辑必须下沉 C++）；三端解析必然漂移 |
| UI 层（Swift）直连 LLM API | 违反红线 1；Android/鸿蒙端要重写一遍；决策校验无法跨端共享 |
| core 内直接实现 socket/HTTP | 传输实现随平台差异大（TLS、代理、后台策略），且 manifest 无先例；PAL 适配层是既定模式（参照 pal/media、pal/inference） |
| AI 决策绕过 CommandHistory 直接改 Timeline | 破坏 Undo/Redo 与"UI 不得直接改模型"红线；无法撤销的 AI 操作是产品灾难 |

## 后果

**正面**
- 特征提取、决策校验、执行映射全在 C++：三端行为一致，UI 层薄。
- EditPlan 是纯数据契约：可单测（schema 合法/非法样例）、可回放、可 diff、可做"AI 建议先预览再应用"。
- 供应商可插拔 + 服务端无状态：不锁死任何一家模型，合规调整成本低。
- 全 Command 化：AI 与人共享撤销栈，"AI 改错了"一键还原。

**负面 / 成本**
- 新增 `pal/net` 与 `ILlmClient` 两个抽象层，首期只有 Apple 一个实现（Android/鸿蒙排 P1+）。
- 纯特征（无原始帧）的决策质量存在不确定性 [hypothesis]，需要真实素材评测。
- EditPlan schema 冻结后变更要走版本化迁移（`cq.editplan/2`），有契约维护成本。

**缓解**
- 特征集设计留 `extensions` 扩展字段与可选帧描述开关（SPEC §5）。
- EditPlan 校验器配 golden 样例集（合法/非法/边界），schema 变更必须 bump 版本号并保留旧版解析。

## 反转条件

1. 平台方开放端侧多模态视频理解模型且覆盖中端机（RAM ≥ 6GB 门槛）→ 重新评估"理解必须上云"。
2. OpenAI-compatible 协议生态碎片化导致多供应商适配成本失控 → 收敛为自建代理协议（改动仅在 `pal/net` 与配置）。
3. 实测证明纯特征决策质量不可接受且用户授权率高 → 提升可选帧上传为默认（需重新过隐私评审）。
