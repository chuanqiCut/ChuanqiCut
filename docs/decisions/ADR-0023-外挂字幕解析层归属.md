# ADR-0023：播放器外挂字幕解析层 v1 用 Swift 纯函数，三端一致需求出现时下沉 C++

- **状态**：已批准（UIA-018/025 实施前置）
- **日期**：2026-10-05
- **相关**：[TASK-UIA-018](../tasks/TASK-UIA-018.md) · [TASK-UIA-025](../tasks/TASK-UIA-025.md) · [PLAN-播放器进阶](../tasks/PLAN-播放器进阶.md) §3 · ADR-0014（UI 域豁免先例）· ADR-0022（播放器内核接缝）· AGENTS 红线 #1

## 背景

外挂字幕（SRT/WebVTT/ASS）进阶版拍板纳入。解析层放哪有两个约束在拉扯：

1. 红线 #1"除 UI 之外的一切下沉 C++"——字幕解析是业务逻辑，三端一致性要求下应在内核。
2. 播放器 MVP/进阶版当前只覆盖 Apple P0（ADR-0022），字幕渲染在 SwiftUI；立即为解析开 C ABI 意味着 `cq_sdk.h`（高冲突文件）+ 绑定层 + 测试宿主的连锁改动，而 Android/鸿蒙侧连播放器都没有。

## 决策

1. **v1/v2 解析以 Swift 纯函数实现**，落 `SharedUI/Player/SubtitleParser.swift`：
   输入 `Data` → 输出值类型 `[SubtitleCue]`（时间轴 + 带 minimal 样式的文本 span），
   无平台依赖、无状态、可被 XCTest 全量覆盖。
2. **归属边界显式声明**（记入 `.ai/modules/ui-apple.md`）：字幕解析是**过渡性 UI 域豁免**
   （先例 ADR-0014 相机 / ADR-0022 播放内核），不是"解析逻辑不归内核"的先例。
3. **反转条件（下沉 C++ 的触发）**：Android（P1）或鸿蒙播放器需要外挂字幕，或内核
   播放 session（P3）落地需要字幕轨参与时间轴——届时把解析器移植为
   `core/src/subtitles/` + C ABI，Swift 侧换薄绑定，**渲染层与数据结构不变**
   （`SubtitleCue` 值类型形状即 C ABI 的设计底稿）。
4. **libass 不引入**（当前）：ISC 许可合规，但 C 库三端编译 + manifest.toml 治理 +
   体积成本，与"样式子集"需求不匹配（UIA-025 明确子集范围）。重新评估条件 =
   产品要求完整 ASS 特效（卡拉OK/矢量/blur）。
5. 渲染层（`SubtitleOverlayView`）与解析层同域文件，但**只消费 `SubtitleCue` 值类型**——
   未来解析下沉时渲染层零改动。

## 备选方案

| 方案 | 否决理由 |
|---|---|
| 立即下沉 C++ + C ABI | 触发 `cq_sdk.h` 高冲突文件与绑定层连锁改动；当前只有 Apple 端消费，收益为零 |
| 引入 libass | 完整 ASS 能力远超"样式子集"需求；C 库三端编译与依赖治理成本不匹配 |
| WebView/系统渲染字幕 | 引入 web 层依赖违背技术栈；系统无公开 ASS 渲染能力 |

## 后果

**正面**：零 ABI 变更；解析器纯函数可测（时间戳/容错/边界全覆盖）；渲染与解析解耦，
下沉时渲染层不动。

**负面 / 成本**：Swift 侧出现第二份格式解析逻辑的潜在归宿问题（素材探测在 C++）——
已在 §3 声明过渡性；ASS 子集与 libass 行为存在偏差（已在 UIA-025 声明还原度）。

**缓解**：`SubtitleCue` 结构即未来 C ABI 设计底稿；下沉任务届时挂 PLAN-播放器进阶 P3 序列。
