# ADR-0019：文档体系分层与归档规则

- **状态**：已批准
- **日期**：2026-10-05
- **相关**：`docs/README.md`（文档地图）、`.ai/source/AGENTS.root.md`（收尾清单）、`.workbuddy/memory/MEMORY.md`（编号纪律原始记录）、RESEARCH-001 §1（第一代文档资产评级）

## 背景

2026-10-05 文档盘点发现的问题（此前积累约两周）：

1. **第一代调研文档堆在仓库根目录**：6 份 `技术调研_*.md` + `技术方案决策书.md` 共约 5500 行。
   它们早在 2026-09-23 就被 RESEARCH-001 批判性评审、被 ARCH-001 与 ADR-0001~0008 吸收/修正/废弃，
   但物理位置未归位，`docs/README.md` 用 `../` 相对链接挂着，新会话极易误读其中的估算数字与已推翻结论。
2. **HANDOFF 位置与编号混乱**：HANDOFF-001 在 `docs/ai/`，002/003 在 `docs/` 根，
   004 双卡撞号（相机线 / 编辑器线各一份且都在活跃更新），无规则说明。
3. **`docs/README.md` 索引腐烂**：ADR 只列到 0008（实际 18 个）、任务卡说 4 张（实际 32 张）、
   状态停在"骨架阶段"，根因是**把易变的状态快照写进了索引**。
4. **`specs/` 前缀体系未成文**：ARCH-（架构方案）/ 功能域-（Spec）/ PAL-（契约）/ AI-ENG-（方法规范）
   四类混在一个目录，命名规则只可意会。
5. **编号纪律只存在于 `.workbuddy/memory/MEMORY.md`**（2026-10-04 双机撞号后所记），
   不属于正式文档规则，新会话若只按 AGENTS.md 走就读不到。

## 决策

1. **六层文档结构**（`docs/README.md` 为唯一地图）：
   `research/`（调研）→ `decisions/`（ADR）→ `specs/`（方案与规格）→ `tasks/`（BACKLOG 总账 + 单卡）
   → `handoff/`（会话交接）→ `ai/`（AI 协作方法）；构建运维文档（BUILD / COCOAPODS）留 `docs/` 根。
2. **仓库根目录不放内容文档**。根目录只保留入口与生成物（README 类、AGENTS/CLAUDE 等）。
   第一代 7 份调研归 `docs/research/legacy/`，每份头部加状态横幅；`AI原生软件工程系统落地记录.md` 归 `docs/ai/`。
3. **legacy 文档只读不删**：头部横幅指明"已被 RESEARCH-001 评审、结论经 ADR 裁决"，保留作评审证据与算法素材。
4. **HANDOFF 全部归 `docs/handoff/`**；新交接取下一个编号（当前最大 004 → 下一份 005）；
   双线并行期间允许**同号双卡**（文件名后缀区分主题，引用时必须带主题）；旧 HANDOFF 只作历史参考，状态以最新为准。
5. **`docs/README.md` 只写稳定内容**（结构、规则、链接），**禁止维护状态快照**；
   "现在做到哪了"一律指向 handoff 与 BACKLOG。
6. **`specs/` 前缀规则成文**：`ARCH-` 架构方案 / `<功能域>-<编号>` 功能 Spec / `PAL-接口契约`（历史遗留，保持不改名）/
   `AI-ENG-` 工程方法；新功能 Spec 用既有功能域前缀，不新造体系。
7. **编号纪律升格为正式规则**（原文自 `.workbuddy/memory/MEMORY.md` 2026-10-04 版）：
   - 任务 ID / ADR / pitfalls P / RESEARCH / HANDOFF 编号**取号前必须 `git fetch` 核对远端已用号**；
   - 撞号处理原则：**改动面小的一侧让位**（引用少、无代码引用的一侧改号），引用清扫按主题上下文精确替换，**禁止全局 sed**；
   - HANDOFF 除外：已分发的交接文件不因撞号改号，用同号双卡消解。
8. 任务卡的 `input` 字段等历史记录引用旧路径的可保留（历史记录不追溯改写）；
   **活文档**（README、HANDOFF、模块文档、未开工任务卡）的路径引用必须随迁移同步更新。

## 备选方案

| 方案 | 否决理由 |
|---|---|
| 7 份根目录文档按 `RESEARCH-003~009` 重新编号入 `research/` | 混淆"我们产出的调研"与"被评审的输入素材"；RESEARCH-001 的评审对象会指向自己体系内的号 |
| specs 拆为 `architecture/` + `specs/` 两个目录 | 30+ 文件引用 `specs/ARCH-*` 路径，迁移收益低于清扫成本与断链风险；用前缀规则成文替代 |
| `PAL-接口契约.md` 改名为 `PAL-001-*.md` | 被 `.ai/modules/` 三份、BUILD.md、任务卡引用；契约文件名是跨文档锚点，改名收益低 |
| HANDOFF-004 双卡之一改号 005 | 两份都在活跃使用且被任务卡 / pitfalls / 日志按号引用（多数不带路径），改号破坏引用语义 |
| 状态快照继续放 README（补数字到最新） | 治标不治本，两周内必然再次腐烂（本 README v1 即证据） |

## 后果

**正面**
- 新会话从 `docs/README.md` 一张图看清全部文档资产与其新旧关系；
- 第一代文档的误用风险被横幅 + RESEARCH-001 双重阻断；
- 编号纪律从工作日志升格为 ADR，双机撞号有章可循；
- README 不再承载易变状态，腐烂源头消除。

**负面 / 成本**
- 引用旧路径的历史日志（pitfalls / workbuddy）与活文档路径不一致，按文件名（不带路径）引用仍可定位；
- legacy/ 目录带中文文件名（git 转义显示不友好），但保留原名是与 RESEARCH-001 评审表对账的关键。

**缓解**
- 引用清扫已覆盖全部带路径引用（活文档 9 处）；链接完整性验证入本轮验收。

## 反转条件

- 若未来引入多语言文档或文档站点生成工具（如 mdBook），目录结构需重新评估；
- HANDOFF 数量超过 10 份后按年份分子目录。
