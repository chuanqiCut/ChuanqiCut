## BIND-002：Swift 绑定层（SPM package）完成

BIND-001 冻结了 C ABI，但 Swift 仍调不到（`bindings/swift/` 只有一个 .gitkeep）。
本任务把 C ABI 包成 Swift package，SPM 路径与独立验证路径**都跑通**。

产出：
- `Package.swift`（三层 target：binaryTarget → C target → Swift target）
- `Sources/ChuanqiCut/`：值类型（Status/Snapshot/ChangeRecord/Capability）+ `Session`
- 头文件用**符号链接**指向 core/include，**不复制**（避免漂移）
- 观察者默认转发主线程（内核在 session 线程回调）；可指定队列
- `changeName` 用 `StaticString`（内核只存指针，String 会悬垂）
- `prepare.sh`（放 xcframework）+ `run_smoke.sh`（独立于 SPM 的验收）

验证：`swift build` 零告警；`swift test` **7/7**；`run_smoke.sh` **PASSED**
（version 0.1.0 从内核取到、submit→版本 1、失败不推进、观察者收到版本 2）。

## 卡住的三个坑（都记进 pitfalls）

1. **库名缺 lib 前缀**（P5，最大坑）：`ChuanqiCut.a` → `-lChuanqiCut` 找不到
   （`-lNAME` 只匹配 `libNAME.a`）。改名 `libChuanqiCut.a` 后 SPM 链接立刻通。
   而且 `swift build` 只编译不链接，一直是绿的 —— 又是「绿灯 ≠ 可用」。
2. **SPM 的 C target 只有头文件不生成 module**（P6）：报 no such module，加 `shim.c` 解决。
   期间还把符号链接的相对路径层数写错过一次。
3. **binaryTarget 的静态库不会自动链接**（P6）：需显式 `linkerSettings`。

另外本机 SPM 需要 `--disable-sandbox`（要写 ~/.swiftpm/security）。

## 约定补充

- **交付给外部工具链的静态库一律 `lib<Name>.a`**（已写进 MEMORY.md）
- Swift 绑定的验收有两条独立路径：SPM（`swift test`）与 swiftc 直编（`run_smoke.sh`）。
  前者验集成，后者在 SPM 出问题时仍能证明「Swift 能调内核」——这次正是靠后者
  先把核心价值验清楚，再回头修集成。

## CocoaPods 集成：架构已交付，环境未通

产出：ChuanqiCut.podspec（Binary/Source 双 subspec）、apps/apple/Podfile、
docs/COCOAPODS.md。SDK 层走 pod（vendored 二进制 + C++ 设置 + 平台分框架），
UI 层走 SPM；硬规矩：ChuanqiCut 不要 pod 与 SPM 同时引（重复符号）。

**环境折腾了很久，结论如下（两个问题并存）**：
1. `~/.gem` 路径有权限限制 → nkf 编译报 "Operation not permitted @ apply2files"。
   换 `--install-dir /tmp/cqgems` 后 nkf 装成功。**排查时先换路径做对照实验**，
   别急着下"环境不支持"的结论（我第一版就错判了）。
2. **Ruby 2.6 确实太老**（传哲指出，我一开始判断错了）：
   ffi 要 Ruby ≥ 3.0、drb 要 ≥ 2.7。所以 Ruby 升级是必要条件。

**但 Ruby 升级这条路本机也不通**：brew 官方脚本只支持 Apple Silicon；
手动 clone brew 后它自己说 Intel 已无 bottles（Tier 3），只能源码编译，
且又撞上同样的 apply2files。已建议 MacPorts（仍提供 Intel 二进制包）。

**因此 podspec 至今没跑过 `pod lib lint`** —— 这是明确的验证缺口，
已写进 docs/COCOAPODS.md §6。按纪律：没过 lint 不能说集成完成。
