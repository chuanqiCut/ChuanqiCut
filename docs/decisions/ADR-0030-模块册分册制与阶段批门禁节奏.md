# ADR-0030：模块册分册制（调研/任务/进度/测试门禁记录按模块归口）与阶段批门禁节奏

- **状态**：已接受（2026-10-07，传哲拍板：「调研、任务、进度、测试及门禁记录按照模块统一管理，记忆及任务进度更新避免撞车；开发中的门禁和真机测试不要那么频繁，阶段性去跑」）
- **关联**：[ADR-0029](ADR-0029-双机分工与门禁跑批节奏.md)（双机分工，本 ADR 修订其「日批」节奏）、ADR-0019（文档分层不变，本 ADR 只加管理归口）、[TODO-POOL-门禁真机待办池](../tasks/TODO-POOL-门禁真机待办池.md)、pitfalls P82
- **影响面**：流程与文档（零代码）；`.ai/modules/*.md` 全部增加「模块册」节；真源「双机分工与门禁节奏」节；PLAN-三线并行 §4~6

## 背景

ADR-0029 建立了双机分工与「待办池 append-only」，但**记录类文件仍是共享大文件**：
pitfalls / baselines / TASK-BACKLOG / tasks 与 docs 的 README / 当日工作日志 `.workbuddy/memory/YYYY-MM-DD.md`
—— 两台机器 append 同一日志文件、同一坑册、同一基线册，P82 的「双机同改管理文档必分叉」
只对池文件立了规矩，其余全局册没有归口。同时调研（RESEARCH-*）、任务（TASK-*）、进度
（散在任务卡/日志/HANDOFF）、测试与门禁记录（散在日志/review/baselines）按**文档类型**分层
（ADR-0019），不按**模块**归口——查一个模块的进度要翻四五种文件。

另外 ADR-0029 定的「集成机每日批次」实践下来偏重：传哲每天定期跑门禁与真机，
开发期内多数日期并没有值得全量验证的增量。

> **2026-10-07 深夜补充（传哲拍板）**：门禁与真机的执行本身也要**先询问传哲**再跑
> （阶段批触发条件不变，触发后人点头）。本 ADR 其余内容不变。

## 决定

1. **模块册 = 模块级唯一管理归口**：`.ai/modules/<模块>.md` 末尾增设「模块册」标准节
   （任务与进度 / 测试与门禁记录 / 调研·决策·池指针）。**该模块的任务、进度、测试及门禁
   记录只更新本节**；本节由**归属线**（PLAN-三线并行 §1a）写入，一机一线故天然单写者。
   新 RESEARCH/SPEC/REVIEW 落 `docs/` 原位（ADR-0019 分层不变），但必须在其归属模块册
   登记指针。
2. **全局册单写者 = 集成机**：`TASK-BACKLOG.md`、`tasks/README.md`、`docs/README.md`、
   `.ai/memory/pitfalls.md`、`.ai/memory/baselines.md`、`PLAN-*.md`、
   `.workbuddy/memory/MEMORY.md`（长期约定）、各 `docs/decisions/ADR-*`——开发机**零直写**，
   需要改 → 池条目或提案，集成机阶段批落地（pitfalls 占号、BACKLOG 登记均走发号器）。
3. **当日工作日志分机**：`.workbuddy/memory/YYYY-MM-DD.md` 仅集成机写主日志；开发机的
   过程记录写进**自己模块册的进度节** + 池条目（来源字段），不再直接写共享日期文件。
4. **门禁与真机改「阶段批」节奏（修订 ADR-0029 §日批）**：
   - **开发期**：开发会话只做模块级自查（编译 + 相关单测），不跑全量门禁，不碰真机。
   - **合并快检（必做，便宜）**：集成机拉远端后先跑窄检——`build_core.sh` + SharedUI
     `swift test`（或 `-typecheck`）+ **双壳 App target 真编译**（iOS `iphonesimulator`
     Debug + macOS Debug，增量约 2~5 分钟；2026-10-07 P83 案底后补入）+ 冲突标记/旧号扫描；
     P78 类「从未编译过」的代码在这一层就能拦住，不必等全量。
   - **阶段批（全量门禁 + 真机一趟多单）**：触发条件 = ①一个 PLAN 阶段/里程碑收尾；
     ②一批相关任务卡闭环（域内功能可观察）；③真机单在池里攒齐一趟；④周度兜底
     （若一周无阶段点）。结果按模块写进各模块册测试记录节 + 池条目关闭。
   - 验收口径不变：全量 `run_gate.sh` 仍是唯一验收；P0 发现即冻结该线合并。

## 后果

- 正向：记录按模块聚合（查一个域只看一个文件）；全局册回到单写者，P82 类分叉根因扩展到
  全部管理文件；门禁从每日全量降为阶段全量 + 合并快检，开发节奏不被验证阻塞。
- 代价：BACKLOG 状态与模块册进度存在**双处登记**——规定 BACKLOG 是 DAG 总账（集成机
  阶段批对账），模块册是活进度（归属线随手更新）；baselines 只留带机器环境的性能数字，
  验证过程记录归模块册。
- 反转条件：合并快检连续两次漏掉远端破损（阶段批才炸）→ 恢复「合并即全量门禁」。
