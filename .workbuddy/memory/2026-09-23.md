## 第二轮更正（传哲 Review 反馈，已全部落地）

传哲给了 4 条纠正，均已反向修订到全部文档与 AI 真源：

1. **Shader 要能单独使用平台特性** → 推翻 ADR-0002 原「禁止平台专属扩展」的单一 Portable 层设计，改为**双层机制**：
   - Portable 层 `shaders/src/*.glsl`（GLSL→SPIR-V→MSL/GLSL ES，禁平台扩展，是功能基线）
   - Platform-Native 层 `pal/<platform>/shaders/`（可用满 Apple Metal 特性：tile shader / imageblock / SIMD-group / MTLTensor 等）
   - 四条硬约束：永远可选、先有 Portable、收益 ≥ 20% 才合入、golden 一致 + 自动回退
2. **性能基线 = 高端满足、中端可用、不适配低端机** → 低端机从「降级运行」改为**明确不支持**（Android 硬件门槛 RAM ≥ 6GB + GLES 3.1）。保留的只有「能力缺失降级」（无硬解→软解、无 compute→fragment），因为中端机也可能缺某项能力，这不属于低端适配。
3. **iOS / Mac 重点支持** → 所有平台表标注 P0 重点；ARCH-001 新增 §2.2；任务 backlog 增加执行顺序说明（Apple 优先）。
4. **MediaPipe 到底引不引入** → 明确回答：**SDK 不引入，模型文件引入**。`face_landmark.tflite`(468 点, Apache-2.0)、`face_detection_short_range.tflite` 作为模型资产入库；Apple 端转 `.mlpackage` 走 CoreML，Android 端走 TFLite GPU delegate；landmark 后处理在 C++ 共享。ADR-0005 新增「决策 0」专门回答此问题。

## 第三轮：TFLite 概念澄清 → 发现 ADR-0005 一处未核实决策

传哲问「TFLite 是啥」。解释文件 vs 运行时之分时顺手核验了官方器文档，发现两个问题并已修订：

1. **术语过时**：Google 已把 TensorFlow Lite 更名为 **LiteRT**。工程内统一写「LiteRT（原 TensorFlow Lite）」，`.tflite` 作为文件格式名保持不变。
2. **ADR-0005 的 Apple 端路径是未核实就选的**：原稿只写了「coremltools 转 .mlpackage」一条路。实际有两条：
   - A 构建期转换（目标方案）：运行时零第三方依赖，但 `coremltools` 对 `.tflite` 的支持**不在官方主列 source framework**，算子覆盖与数值一致性未实测。
   - B 运行时 delegate（回退）：直接发 `.tflite` + LiteRT 的 CoreML delegate，官方支持、A12+ 自动走 ANE，但官方仅支持 FP32/FP16，且要引入一个第三方运行时。
   已加 §0.1 双路径对比表、选 A 备 B、并规定 **AI-013 spike 是生死判定**（转得出 / 数值对得上 / 跑得通），不过就切 B，不许边写业务边试。

修订文件：ADR-0005（§0 术语 + 新增 §0.1 + 决策 4 前置条件 + 负面成本 + 修订记录 + 反转条件 + 落地任务）、ARCH-002 §7.1、`.ai/modules/ai.md`（新增术语区分与双路径表）、`.ai/memory/pitfalls.md`（新增 R8/R9）。
