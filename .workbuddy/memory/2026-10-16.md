## #21 旋转修复（GPU blit UV 旋转，回退 Core Image 解码旋转）

- 根因：此前在解码阶段用 Core Image 对像素旋转，触发无标签 BGRA 缓冲的色彩空间转换 → 色偏。
  用户要求改到 GPU 层（blit 的 UV 旋转），不动色彩空间。
- 改动链路（11 文件）：decode 仅下发 `rotation` 元数据（不旋转像素）→ preview `Acquire(out_rotation)`
  → `ChqRenderNodeDesc.source_rotation`（Prepare 回填）→ evaluator Encode 用旋转后尺寸算视口 +
  把 rotation 传给 `ChqIBlitPass::Encode` → blit 在共享顶点缓冲重烤 UV（`RotateUv`/`BakeRotation`）。
- 编译期抓到并修复**截断 bug**：旋转角全程用 `uint8_t` 存，270>255 → `static_cast<uint8_t>(270)=14`，
  会静默丢失 270° 源（iPad 竖屏）的旋转。把 `ChqVideoFrame.rotation` / `rotation_deg_` /
  `source_rotation` / `last_import_rotation_` / `cached_rotation_` / `frame_rotation` / `src_rotation`
  / `DeriveRotationDeg` 返回值 / blit `RotateUv`·`BakeRotation` 形参 / evaluator 局部 `rot` 全部改 `uint16_t`。
- iOS + macOS 双壳构建均 **BUILD SUCCEEDED，0 错误，无新增 warning**。
- 真机复验：传哲已同意并装机。devicectl install 成功（bundleID com.chuanqi.cut），foreground launch
  （CQ_AUTO_ROUTE=editor + CQ_DEBUG_OVERLAY=1）已就绪。**待传哲真机填写问卷（5 项：竖屏朝向正确+
  色彩无偏、滑动流畅、缩略图清晰、绿字帧率、音频回归）；问卷回收前不标记 #21 完成**。
  注：当前工作树含 TimelineKit 迁移 WIP，一并打进包；若崩溃需带 --console 重启动取证。
- **真机首轮反馈：画面倒立（旋转方向反 180°）**。根因：blit 把显示旋转角 R 直接传给 RotateUv，
  但 UV 层须施加 R 的逆（uv_s = Rot^{-1}(uv_d) 才还原 display = Rot·encoded）；昔日推导误判
  RotateUv(90)≡RotateUv(270)（实际差 180°）。修 `blit_pass.mm` Encode：传 `(360-R)%360` 给 BakeRotation。
  已重构建 + devicectl 重装机 + 前台 relaunch，待传哲复核朝向不再倒立。

## 轨道 scrub 卡顿：P142 全套实施（传哲 2026-10-16 定方案「滑动时快速 seek + 控制频率 + 结束走一次精准 seek」）
- 根因（已核实）：scrub → `onScrub` → `setPlayhead` → 泵线程 `ChqSeekPolicy::kExact` 精确 seek，
  **每次从最近关键帧重解整个 GOP**；长 GOP 解码占满单核、与滚动主线程抢核 → 拖动卡顿（逆向更贵）。
  核心 `ChqSystemFrameProvider` **早已实现** kKeyframeBefore/kNearest，被「Platform 接缝不携带 policy」挡死。
- 全链路打通（`ChqSeekPolicy` 用中立 `int32_t` 跨接缝，因 `chq_frame_provider.h` 已 include
  `chq_media.h`，反向 include 会成环）：
  - `chq_media.h`：`ChqIFrameProvider::Seek/AcquireFrame` 末尾加默认参数 `int32_t seek_policy=0`。
  - `chq_platform_frame_provider.cpp`：**删掉「非 kExact 一律拒绝」**，改为透传。
  - `frame_provider_apple.mm`：`CqFrameProvider` 接收 policy，`static_cast<ChqSeekPolicy>` 转发。
  - `chq_preview_frame_source.h`：`RenderFrame(..., int32_t seek_policy=0)`（放**末位**，保住既有 3 参调用）。
  - `chq_preview_pump.h/.cpp`：`Request(pts, seek_policy=0)` + 成员 `requested_seek_policy_`，`Loop` 透传。
  - `chq_preview_renderer.h/.cpp`：`RenderFrame` 入口存成员 `seek_policy_`，`Acquire` 读它
    （**不沿 RenderGraph 逐层传参**：同帧内恒定 + 同在泵线程无竞争，且不改 `ChqIFrameSource` 契约）。
  - C ABI：新增 `cq_preview_pump_request_ex(..., int32_t seek_policy)`；原 `cq_preview_pump_request` 保留走 kExact。
  - Swift：`PreviewPump.SeekPolicy`(exact/keyframeBefore/nearest) + `request(pts:policy:)`。
- UI（`EditorViewController` + `EditorTimelineKitView`）：
  - 拖动中 `onScrub`：`policy:.keyframeBefore` + **限频 24Hz**（`scrubSeekInterval`）；
    置 `isScrubbingTrack`，使 `syncPreview` 的 renderEpoch 补帧**也**走廉价策略（否则会盖掉限频成果、白做精确解码）。
  - 新增 `onScrubEnded` 出口（`EditorTimelineKitView.endUserScrub` 触发）→ 松手补一次 `.exact` 精确帧。
- 验证：iOS 壳 **BUILD SUCCEEDED**（0 错）；`build_core.sh --platform=apple` 通过；
  `ctest -R "preview_pump|preview_renderer|system_frame_provider|c_abi_preview|sequential"` **6/6 PASS**
  （含 `media_sequential_real` 真素材 69s）。新增断言：预览泵第 9 组「seek 策略透传」验证 0/1/2 原样到达渲染器。
